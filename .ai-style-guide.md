# Aire Claro, AI Style Guide

The visual contract. Read it before adding a **new component** or changing a
**token**; a one-off tweak to an existing component doesn't need a full read.
For a new interactive control, reach for a **shadcn/ui primitive**
(`components/ui/`, §5) before hand-rolling one; otherwise copy the nearest
approved component rather than inventing a value.

Approved surfaces: the **Navbar** (`components/navbar/`), and the map's **Capas**
panel, **Actualizado** badge, **info dialogs** and **estación card**
(`components/mapa/mapa-sensors.tsx`).

Tailwind (`tailwind.config.ts`) extends stock with three named panel widths and
the **shadcn/ui token bridge** (`bg-background`, `text-muted-foreground`,
`border-border`, … → `hsl(var(--…))` in `app/globals.css`), carrying the house
palette (warm grays, blue-600 primary). The air-quality scale is **not** a
token — it lives in `lib/air-quality.ts`. Font is **Inter** (`next/font/google`,
latin + latin-ext, `display: swap`), on `<body>`.

**Readings are per-station.** Every reading on screen is tied to a named
station, or is a *coverage* statement ("15 estaciones · 160 sensores
reportando"). The field of coloured discs is the "at a glance".

**The app is light-only.** No dark theme, no `dark:` variant anywhere. A real
dark theme is its own project with its own pass over every token; don't add one
ad hoc.

## 1. Layout and containers

### Breakpoints
`md:` (768px) is the main desktop switch and carries almost everything; `sm:`
(640px) and `lg:` (1024px) handle a few container/footer cases. No `xl:` /
`2xl:`, only the `max-w-7xl` content cap. Reach for `md:` first.

### Page shell
| Element | Classes |
|---|---|
| Root wrapper | `flex min-h-svh flex-col` |
| `<main>` | `w-full flex-grow overflow-y-auto bg-gray-50` |
| Header height | `h-header` (`--header-h`: `52px` mobile, `72px` at `md`) |
| Map viewport | `h-below-header` |

Never restate `52px` / `72px` or write `h-[calc(100svh-52px)]`; use the utilities.

**Chrome bars** (desktop `SiteHeader`, mobile top bar, mobile bottom nav) are
opaque `bg-stone-50` strips in normal flow, not floating panels — so they take a
**`border-stone-200` hairline** on the edge facing the content (`border-b` on
the top bars, `border-t` on the bottom nav), **never a shadow**. The warm stone
line, not the panels' cool `gray-200`, since the strip is warm-toned. The
bottom nav keeps its `.glass` fill but zeroes the x/b borders and recolours the
top one to `border-t-stone-200`.

### Content pages (non-map)

|---|---|
| Wide / data pages | `mx-auto max-w-7xl px-6 pb-24 pt-16 lg:px-8 lg:pt-28` |
| Prose pages | `container mx-auto max-w-2xl px-4 pb-10 pt-8 md:pt-6` |
| Footer inner | `mx-auto max-w-7xl px-6 pt-24 pb-8 md:py-8 lg:px-8` |

### Map overlay panels (named widths)

### The two rails
Every floating element sits on one of two optical rails:
- **Surface rail, 24px** (`left-6` / `right-6`): where a panel's *edge* lands.
- **Text rail, 44px**: where a panel's *text* lands (24px surface + 20px `px-5`).

The desktop header is asymmetric on purpose (`pl-11 pr-6`): the bare logo has no
surface, so it's pushed to the 44px text rail to line up with "Capas" below it.
Artwork that leads with a curve crosses its rail 1–3px for optical level (the
desktop logo carries `-ml-0.5`); a text label sits on the rail exactly.

### Floating-panel anchors
| Anchor | Classes |
|---|---|
| Capas column | `absolute left-4 top-4 md:bottom-10 md:left-6 md:top-6` (legend pill pinned at foot with `md:mt-auto`; freshness is its footer row) |
| Right card column | `absolute right-6 top-6 md:bottom-10` (card only; `flex-1` wrapper fills the column height) |
| Mobile Capas button | `fixed right-6` + `bottom: calc(3.5rem + env(safe-area-inset-bottom) + 6.5rem)` (1rem above the 5.5rem peek sheet) |

`bottom-10` (40px) is the working margin — below it collides with Mapbox's logo
and attribution; re-check on a real map before dropping it.

Overlay containers are `pointer-events-none`; each interactive child re-enables
with `pointer-events-auto` so the map stays draggable through the gaps.

### Air-quality scale
Never hardcode. Import from `lib/air-quality.ts`.

Two tokens per level. `color` is the official NOM-172 hue, for anything with
**area** (fills, legend swatches, the pulse halo). `ink` is
that hue darkened only as far as it needs to clear **3:1 on white**, for
everything on a light ground that is **not** a fill (bold quality headline,
hairlines, 1px rings, the marker rim). Nothing using `ink` is body text, so 3:1
is the correct floor.

| Level | ≤ | `color` (fills) | `ink` (≥3:1, hairlines/bold) |
|---|---|---|---|
| Buena | 15 | `#00e400` | `#00a400` |
| Aceptable | 25 | `#ffff00` | `#ad8900` (gold — no honest dark yellow at any floor) |
| Mala | 79 | `#ff7e00` | `#de6e00` |
| Muy mala | 130 | `#ff0000` | `#ff0000` |
| Extremadamente mala | ∞ | `#8f3f97` | `#8f3f97` |

- **Pure `color` is the legend key only; every data surface uses the calmed
  mix** — `color` nudged ~25% toward `ink` (`getMarkerFill` / `getMarkerFillHex`,
  `MARKER_INK_MIX`). If the marker field reads too electric, raise
  `MARKER_INK_MIX`, don't re-darken `ink`.
- **A chart dot for a single reading** takes `color` for its body and that
  level's `ink` for its 1px ring. (For `/datos` charts when they land — the map
  card no longer has a trend chart.)
- **The estación-card quality headline** is `ink` (bold coloured text) — the
  status word is the card's most important element and stays coloured.
- `pm25 === null || pm25 <= 0.4` → nothing for a citizen sensor; a SIMA station
  renders grey (`nodata`, §5).
- **Pollutant is PM2.5, stated not filtered.** The map shows one pollutant by
  choice, not limitation. It appears on the reading (`µg/m³ PM2.5`) and as the
  `PM2.5 · µg/m³` line in the expanded legend, which carries a small `Info`
  button → one-paragraph `InfoDialog` ("qué es PM2.5"). **Not** a Capas filter
  row and **no** "PM10 / no disponible" rows anywhere.

| Nav label | `text-sm font-medium`, current page `font-semibold` |
| Eyebrow label | `text-xs font-medium uppercase leading-none tracking-wide text-gray-400` |
| Meta, counts | `text-xs text-gray-500` |
| Micro numbers, axis | `text-[11px] leading-none` / `text-[10px] font-medium` |

| Footer legal | `text-xs text-gray-400` |

- `tracking-wide` only with `uppercase`. Nothing else gets tracking.
- `leading-none` on labels / single-line meta; `leading-relaxed` on any
  paragraph of Spanish copy.
- Weights: `font-medium` (500), `font-semibold` (600), `font-bold` (700). No
  `font-light`, no `font-extrabold`.
- Truncate rather than wrap in chrome: `min-w-0 flex-1 truncate`;
  `whitespace-nowrap` on chips / buttons that must hold width.
- "label · summary" is the house pattern for a collapsed header: bold label,
  then `· ` + muted summary.

## 5. Components

### shadcn/ui primitives
Interactive primitives live in `components/ui/`, added with
`pnpm dlx shadcn@2.10.0 add <name>` — **pinned to the 2.x CLI** (this repo is
Tailwind v3; the v4 CLI forces a Tailwind-v4 + Base-UI setup). They're Radix +
`cva` on the token bridge, so focus trap / keyboard nav / ARIA come for free.
Retune each to the house language the first time it's used: the neutral 2px
focus ring at 15% ink (never the accent), the §5 radius scale. `Button` (incl.
`nav` variant), `Card`, `Chart` are done.

**Charts** are **Recharts** via the shadcn `Chart` wrapper. Air-quality series
pull from `lib/air-quality.ts`; the `/datos` charts' own good/bad pair
(días insalubres, cobertura de estaciones) lives in `lib/datos-colors.ts`
(`COLOR_SALUDABLE` / `COLOR_INSALUBRE`) — a bespoke pastel green/red,
pixel-matched to a user-supplied reference rather than the dataviz skill's
validated palette (that palette was tried and explicitly overridden; see
memory). `--chart-1..5` remain unused/provisional for a future generic
categorical series. `recharts` pinned at `2.15.4`.

**The map keeps its bespoke interaction components on purpose** — the info
popups on the platform `<dialog>` (top layer, native focus trap), the 2-state
mobile sheet, the legend / health-recs. What the map took is `.glass`. New
shadcn primitives are for `/datos` and the navbar/footer when next touched.

| Radius | Where |
|---|---|
| `rounded-full` | nav pills, dots, tooltips-as-chips, grabber |
| `rounded-3xl` (24px) | dialogs, bottom sheets (`rounded-t-3xl`) |

### The map
The marker field is one Mapbox GL **circle layer** (`FIELD_LAYER`), a `symbol`
text layer for the printed numbers (`FIELD_LABEL_LAYER`), a `symbol` layer for
the SIMA badges (`SIMA_BADGE_LAYER`), and one DOM `Marker` for the selected
station. Mechanics — `buildFieldData` / `updateField` / `syncActive` /
`feature-state` / camera — are in `docs/architecture.md`.

**Rejected, don't re-propose without the user asking:** any painted layer
(clustering, density heatmap, IDW gradient, IDW contour bands, IQAir-style flat
tint); a squircle or any shape-coding of the network; a metro-wide / median
value on the card or legend; locate-me / "air near me".

Rules:
- **Every marker is a disc.** The network shows in *weight and marks*, never
  *shape*. SIMA reads apart by a fuller disc, the `Landmark` corner badge (on
  **every** SIMA station always, grey no-data ones included), and draw order
  (`circle-sort-key` = `(isSima ? 1e6 : 0) - lat` — SIMA over citizen, south
  over north; latitude and provenance only, **never the reading**, so an overlap
  is never biased toward one end of the scale).
- **Disc look:** fill is the calmed mix (`getMarkerFillHex`), **matte, no
  gloss**, flat **1.5px white stroke**, no shadow. `circle-opacity` rests at
  **0.82 SIMA / 0.62 citizen** so overlaps read as density. Radius is
  zoom-interpolated (`FIELD_RADIUS`), SIMA a step fuller.
- **SIMA is the calibrated spine; PurpleAir is uncorrected texture** — not
  methodologically comparable (methodology doc). The weight split says so.
- **Selected station** is a DOM marker (only a DOM element can carry the CSS
  pulse halo): opaque fill, `--dot-scale: 1.25`, halo in the sensor's own
  `color`, solid `2px #111827` focus outline (the house ring vanishes over map
  imagery). Its GL disc + field badge are hidden.
- **No-data:** a citizen sensor with no reading drops out of the source; a SIMA
  station stays as a grey disc (`#9ca3af`, `circle-opacity` 0.5) — the network
  is fixed, its gaps matter. A selected grey station doesn't pulse, and its
  disc/DOM marker prints no number (there is none).
- **Every disc with a reading tries to print its PM2.5 number.** No zoom-gated
  fade-in — tried once, reverted the same day: it read as the numbers
  "loading in" during the opening flyTo, not deliberate. Label *visibility* IS
  collision-detected (`text-allow-overlap`/`text-ignore-placement` both
  `false`) — where circles genuinely overlap on screen, so would their
  centered numbers, and there's no rendering trick around that; a disc with no
  room for its label goes unlabelled (still coloured, still in the card and
  every `aria-label`) rather than smearing digits over its neighbour's. This
  is the standard technique every point-label map layer uses (Mapbox/Google
  POI labels) and is the second thing tried here — `allow-overlap: true`
  (every disc labelled unconditionally) came first and was reverted for
  producing exactly the blotchy overlap this avoids; collision-hiding then
  briefly got reverted too (mistaken for the cause of a separate "loading in"
  bug that was actually the zoom fade) before landing here for good.
  `symbol-sort-key` reuses the same provenance+latitude key the circle draw
  order uses, so which label wins a collision is still never a function of
  the reading. Straight on the fill, no shape behind it (a white core / centre
  lens / `-webkit-text-stroke` were all tried earlier too and read as a
  sticker or vibrated — flat ink on the fill is the one that held up). Ink is
  picked per level by fill luminance (`getMarkerNumberInk`): near-black on
  four levels, white on Extremadamente mala's purple — each pairing clears
  4.5:1 on its own fill. Disc radius (`FIELD_RADIUS`/`fieldRadiusAt`,
  field-layer.ts) is derived from `FIELD_LABEL_SIZE` (diameter ≈ 2.4x the text
  size) so the number has room in the first place. The selected station hides
  its GL label and prints its own, larger number on the DOM marker instead
  (`--marker-number`, `.sensor-marker--selected` bumps to `font-weight: 600`;
  its font-size is set in JS by `resizeSelectedMarker`, not CSS — a fixed
  value there would win over the inherited size). Also on
  the estación card (with its word label) and in every marker's `aria-label`
  — color is never the only channel.
- **Selected marker size tracks the field's zoom curve, not a fixed px.**
  `resizeSelectedMarker` (mapa-sensors.tsx) reads `fieldRadiusAt` — the same
  stop table `FIELD_RADIUS` is built from — and sizes the DOM marker to
  `MARKER_LEAD_FACTOR` (1.3) times its own category's (SIMA/citizen) field
  radius, on selection change and on every `zoom` tick. A flat 27/24px was
  tried and silently broke "selected leads by size" once the field was sized
  up: by the map's own resting zoom (11) an ordinary SIMA field disc had
  already grown past it.
- **Keyboard:** canvas discs aren't tabbable, so every station is also a
  visually-hidden `<button>` (`a11yStations` / `selectFromList`) that selects it
  and eases the camera in.

### Tooltip
Two kinds, split by **where they sit**:
- **Hint tooltip** (an icon's label, a transient hint over page content): dark,
  transient, single line. `pointer-events-none … rounded-lg bg-gray-900 px-3
  py-1.5 text-xs text-white shadow-sm`. No live case now; keep the recipe.
- **Chart tooltip** (anything anchored inside a plot area): light, near-solid.
  `bg-white/95`, `border border-black/[0.08]`, `backdrop-blur-[6px]`,
  `shadow-[0_6px_24px_rgba(0,0,0,0.1)]`, dark text (`text-gray-700`, values
  `font-medium`). Radius follows size: `rounded-xl` for a padded multi-row card,
  `rounded-lg` for a single-line pill. A chart tooltip stays light even when it
  carries only a label — one rule per surface.

**Placement.** A chart tooltip tracks the cursor on x only, pinned to a fixed y
just inside the plot area's top edge (`top: 0`, `translate(-50%, 6px)`), and
never crosses that edge (the card's PM2.5 headline sits right above it). Pad the
value domain (15%) so the peak never reaches the pinned band; clamp x to
`clamp(70px, <x>%, calc(100% - 70px))`.

### Motion
| Effect | Value |
|---|---|
| Color / background | `transition-colors` (150ms) incidental; `duration-200` on anything the user directly drives; `duration-300` on scrims and full-panel fades |
| Chevron disclosure | `transition-transform duration-200` + `rotate-90` open (`-rotate-90` for a panel opening upward) |
| Scrim | `transition-opacity duration-300` |
| Disclosure body | `.disclosure-in`, 180ms ease-out, fade + `translateY(-4px)`; `.disclosure-in-up` mirrors it |
| Dialog | `dialog-in` 160ms ease-out, fade + `scale(0.97)` |
| Marker hover | `circle-radius` ×1.14 (`feature-state hover`) |
| Marker selected | `marker-pulse` 2.4s ease-out infinite, halo behind the DOM dot |
| Fresh-data dot | `animate-ping` on the green halo only |
| Map camera | one opening `flyTo`, `OPENING_MOVE_MS` (4500ms), zoom 8 → 11 on the default station (13 for `?sensor=`, 10.5 if none); `jumpTo` under reduced motion |

Chevrons rotate toward the content they reveal, never swapped for another glyph.
A disclosure anchored to the foot of its column (the desktop legend) keeps its
trigger on the bottom edge and unfolds upward (`flex-col-reverse` to paint the
trigger last while keeping it first in the DOM). Disclosures animate **in
only** — an exit animation keeps controls in the tab order after they're gone.

**Map camera.** One move: the opening `flyTo`, run once (`didOpeningFlyRef`).
Use `flyTo`, not `easeTo`, for any move over ~2 zoom levels — `flyTo` runs the
van Wijk curve that holds *perceived* zoom speed constant; `easeTo` interpolates
the zoom number linearly and reads as slow-then-lunge. Don't pass `flyTo` a
custom `easing`. Padding is set instantly, not interpolated. `essential: true`
pairs with a `prefersReducedMotion()` check that swaps the whole move for a
`jumpTo`. `easeTo` is only for small nudges.

Every looping animation has a reduced-motion escape
(`motion-reduce:animate-none`, or a `prefers-reduced-motion` block in
`globals.css` that stops the loop and leaves a static low opacity).

## 6. Accessibility invariants

Fixed deliberately. Preserve them.

- Text hits 4.5:1, non-text controls hit 3:1 — that's why the gray tokens are
  the values they are.
- **Colour is never the only channel.** The freshness dot is backed by a real
  timestamp. Every marker with a reading also prints its PM2.5 number, the
  selected reading is on the card with its word label, the legend maps every
  colour to its label, and every marker's `aria-label` carries the full
  reading. A grey no-data SIMA marker announces "…, sin lectura"; the card
  shows "No disponible" as text.
- Every icon-only control has `aria-label`; decorative icons `aria-hidden`. The
  card / sheet X is `aria-label="Cerrar"`; Escape closes the card (guarded so an
  open `<dialog>` gets Escape first).
- Disclosures wire `aria-expanded` + `aria-controls`; the panel stays mounted
  with `hidden` so `aria-controls` always resolves.
- Async status is announced through a separate `role="status"` `sr-only` node,
  not by mutating a disabled button's label.
- Messages persist until dismissed. Nothing important disappears on a timer.
- External links carry `<span className="sr-only"> (abre en una nueva pestaña)</span>`.
- `prefers-reduced-transparency: reduce` is handled globally (§3).
- **Forced colors (Windows High Contrast) is not handled — the next real gap.**
  When addressed: one `@media (forced-colors: active)` pass over every token,
  lean on system colors, `forced-color-adjust: none` only where an air-quality
  fill must survive (legend swatches, markers). A half pass is worse than none.

## 7. Quick checklist for a new component

1. Floating over the map? `.glass`, `rounded-2xl`, on the 24px surface rail.
2. Header text? `px-5 pt-4 pb-3`, `text-base font-medium text-gray-700`.
3. Body copy? `text-sm leading-relaxed text-gray-500`.
4. Eyebrow? `text-xs font-medium uppercase leading-none tracking-wide text-gray-400`.
5. Rows? `py-3.5`, `border-t border-gray-100`, `hover:bg-gray-100/70`.
6. Any focusable element? The `ring-2 ring-gray-900/15` house ring, no exceptions.
7. Any animation? A reduced-motion fallback.
8. Any air-quality colour? From `lib/air-quality.ts`.
9. Any Spanish copy? Sentence case, no em-dashes.
10. Reusing a named value? Import it. Third copy of an inline value → lift to a const.
11. Shareable map state? Route it through `lib/map-url-state.ts` (History API).
12. Verify with `pnpm exec tsc --noEmit` then `pnpm build` (`pnpm lint` is
    broken; `pnpm build` always logs one `DYNAMIC_SERVER_USAGE` on `/`).
