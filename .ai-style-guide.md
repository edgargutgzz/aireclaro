# Aire Claro, AI Style Guide

The visual contract for this app, extracted from the sections that are already
approved: the **Navbar** (`components/navbar/`), and the map's **Capas** panel,
**Actualizado** badge, **info dialogs**, **estación card** and **time scrubber**
(`components/mapa/mapa-sensors.tsx`).

Read this before writing any UI. When a new component needs a value that is not
here, copy the nearest approved component rather than inventing a token.

**Editorial invariant (constrains the UI).** The platform reports what a
**named station or sensor measured**. It never publishes a metro-wide verdict,
headline number, or aggregate ("Zona Metropolitana: Mala"). Every reading on
screen is tied to a station; the field of coloured discs is the "at a glance".
This killed a metro-median legend caret. Anything filling a rail must stay at
that altitude — a named station's reading, or a *coverage* statement
("15 estaciones · 160 sensores reportando") — never a characterization.

Tailwind runs with a near-default config (`tailwind.config.ts`); the only
extensions are three named panel widths. Everything else below is stock
Tailwind, used consistently. Font is **Inter** (`next/font/google`, latin +
latin-ext, `display: swap`), applied on `<body>`.

## 1. Layout and containers

### Breakpoints
Stock Tailwind, and the set actually in use is short: `md:` (768px) is the
main desktop switch and carries almost everything; `sm:` (640px) and `lg:`
(1024px) handle a few container and footer cases. There is no `xl:` / `2xl:`
in the codebase, only the `max-w-7xl` content cap. Reach for `md:` first; add
another stop only when `md:` genuinely cannot express the change.

### Page shell
| Element | Classes |
|---|---|
| Root wrapper | `flex min-h-svh flex-col` |
| `<main>` | `w-full flex-grow overflow-y-auto bg-gray-50` |
| Header height | `h-header` (CSS var `--header-h`: `52px` mobile, `72px` at `md`) |
| Map viewport | `h-below-header` (`calc(100svh - var(--header-h))`) |

`--header-h`, `.h-header` and `.h-below-header` are defined once in
`app/globals.css`. Never restate `52px` / `72px` or write
`h-[calc(100svh-52px)]`; use the utilities.

### The two rails
The page has two optical rails and every floating element sits on one of them:

- **Surface rail, 24px** (`left-6` / `right-6`): where a panel's *edge* lands.
- **Text rail, 44px**: where a panel's *text* lands (24px surface + 20px `px-5`).

The desktop header is therefore asymmetric on purpose: `pl-11 pr-6`. The bare
logo has no surface of its own, so it is pushed to the 44px text rail to line
up with "Capas" below it; the nav's last pill already reaches the text rail
through its own `px-5`, which holds only as long as that pill is unfilled. The
moment the last pill carries a background it becomes a surface and its edge,
not its label, is what the eye measures, at 24px. See the nav pill below.

**Artwork on a rail gets optical overshoot; text sits on the rail exactly.**
A rail is measured by eye, not by bounding box, so a form that leads with a
curve has to cross the rail slightly to look level with the flat stems above
and below it. The desktop logo is the live case: at `pl-11` its ink and the
nav's "Mapa" label both landed within 1.5px of 44px, and the logo still read
as the more indented of the two, because its leading mark is a ~28px circle.
It carries `-ml-0.5` so the tangent sits at 42px and the mark's optical centre
reads at 44. Keep overshoots in the 1 to 3px band and spend them on curves and
on lockups that are much taller than the text opposite them, never on a text
label, which is already where it looks.

## 3. Color

**The app is light-only.** There is no dark theme and no `dark:` variant
anywhere in the codebase. Do not add one ad hoc; a partial dark mode is worse
than none. If a real dark theme is ever wanted it is its own project, with its
own pass over every token below.

### Surfaces
| Role | Value |
|---|---|
| App background | `bg-gray-50` |
| Header background | `bg-stone-50` |
| Footer background | `bg-stone-100` |
| **Glass panel** (the signature) | `border border-white/60 bg-white/80 shadow-sm backdrop-blur-md` |
| Glass panel, hovered | `hover:bg-white/90` |
| Glass panel, active/pressed state | `border-gray-900/30 bg-white/90` |
| Dialog surface (opaque) | `border border-gray-200 bg-white shadow-xl` |
| Dialog scrim | `::backdrop` `rgb(0 0 0 / 0.4)` + `blur(6px)` |
| Sheet scrim | `bg-black/20` |
| Opaque sheet | `bg-white` + `shadow-[0_-4px_20px_rgba(0,0,0,0.08)]` |
| Peek-state sheet | `bg-white/80 backdrop-blur-md border-t border-white/60` |
| Nested card | `bg-white` inside `bg-gray-100/80` |
| Row tint (expanded), in chrome | `bg-gray-50/60` |
| Row tint (expanded), in a dialog | `bg-gray-50` — opaque; a dialog `InfoSection` body is a reading surface and the `/60` tint clipped its contrast |
| Inline detail block | `bg-gray-50` |

The glass recipe is the app's identity, and it belongs to *chrome that floats
in the workspace*: every floating map panel and chip uses it at `bg-white/80`.
It does **not** extend to dialogs. A dialog holds paragraphs of Spanish copy
over a saturated map, and at `bg-white/90` the map's colour still bled through
enough to push the body text under 4.5:1. Dialogs are opaque white
on a visible `gray-200` hairline; the scrim (dimmed and lightly blurred, `/0.4`
+ `blur(6px)`) is what makes the panel read as floating, so the panel itself
does not have to be translucent to earn the effect. This is the Vercel / Linear
/ Stripe / GitHub convention: translucency for HUD chrome, opaque paper for
reading surfaces.

Because a dialog *is* the reading surface, its copy is set one notch stronger
than chrome body text: `text-[15px] text-gray-600` for paragraphs (chrome stays
`text-sm text-gray-500`), its expanded-row grounds are opaque `bg-gray-50` not
`/60`, and `DialogLink` carries `font-medium text-gray-700` so a link out-weighs
the prose around it. See §4.

The glass recipe has a **reduced-transparency escape**, the same way every
looping animation has a reduced-motion one. A
`@media (prefers-reduced-transparency: reduce)` block in `app/globals.css`
drops `backdrop-blur-*` and takes every near-white translucent fill
(`bg-white/70` through `/95`) to solid `#fff`. It overrides the utilities in
place because the recipe is copied onto each component, not a shared class; if
a `.glass-*` class is ever introduced, the escape moves onto it. Scrims keep
their translucency, they carry depth rather than text. Nothing new is needed
per component: use the recipe and the escape already covers it.

### Text
| Role | Token | Notes |
|---|---|---|
| Primary heading / value | `text-gray-800` | dialog titles, active row labels |
| Panel title, body strong | `text-gray-700` | "Capas", "Calidad del Aire" |
| Secondary body | `text-gray-500` | paragraphs, summaries, muted labels |
| Nav resting label | `text-gray-600` | 4.5:1 floor, never `gray-400` |
| Tertiary / eyebrow | `text-gray-400` | uppercase micro-labels, icons |
| Counts, row summaries | `text-gray-500` | at `text-xs`; these carry data, so they clear 4.5:1 |
| Disabled / pending | `text-gray-500` | plus a standing cue: the `Próx.` badge on desktop, a bare `h-1.5 w-1.5` `bg-gray-400` dot on the mobile bar where the badge does not fit three-across |
| Inverse | `text-white` on `bg-gray-900` |

**Contrast rules that are already settled, do not undo them:**
- An unselected nav label is `gray-600`, not `gray-400` (2.5:1 fails).
- A dialog's close X is `gray-500`, not `gray-400` (needs 3:1 as the only exit).
- Counts and row summaries are `gray-500`. `gray-300` was 1.47:1 and is now
  reserved for pure furniture: the sheet grabber, an em-less placeholder dash.
- The Actualizado chip puts its *value* (the time) in `font-medium
  text-gray-700`; `gray-500` is only the quiet half ("Actualizado"), never a
  chip's only text.

### Air-quality scale
Never hardcode these. Import from `lib/air-quality.ts` (`IMECA_LEVELS`,
`getPM25Color`, `getQualityInfo`, `getLevel`).

Two tokens per level. `color` is the official NOM-172 hue, untouched, for
anything with **area**. `ink` is that same hue darkened (saturation held) only
as far as it needs to clear **3:1 on white**, for everything on a light ground
that is **not** a fill: the card's quality headline (24–30px bold — WCAG
large-text floor, not the 4.5:1 body-text one), hairlines and 1px rings, the
sparkline dot rings and threshold guides, the marker rim. Nothing that uses
`ink` is body text, so 3:1 (large text / non-text objects) is the correct
floor; tuning to 4.5:1 was leaving vividness on the table for no accessibility
gain.

| Level | ≤ | `color` (fills) | `ink` (≥3:1, hairlines/bold headline) |
|---|---|---|---|
| Buena | 15 | `#00e400` | `#00a400` |
| Aceptable | 25 | `#ffff00` | `#ad8900` (nudged to gold — no honest dark yellow at any contrast floor) |
| Mala | 79 | `#ff7e00` | `#de6e00` |
| Muy mala | 130 | `#ff0000` | `#ff0000` (already passes 3:1) |
| Extremadamente mala | ∞ | `#8f3f97` | `#8f3f97` (already passes) |

`MARKER_INK_MIX` (marker fill = `color` mixed toward `ink`) was tuned against
the old, darker `ink`; with `ink` now closer to `color`, that mix calms the
map markers less than it used to. If the marker field reads too electric
again, raise `MARKER_INK_MIX`, don't re-darken `ink`.

`pm25 === null || pm25 <= 0.4` renders nothing for a **citizen** sensor. A
**SIMA** station with no reading for the frame renders a grey `.sensor-marker--nodata`
disc instead (§5 map) — the network is fixed, so its gaps are worth showing.

The **government (SIMA) markers carry a badge** (`.sensor-marker__badge` in
`globals.css`): the `Landmark` glyph the Capas panel and estación card already
use for "gobierno", in a 16px `gray-500` disc (white glyph) with the same 1.5px
white casing ring the marker carries, pinned to the disc's upper-right so it
overlaps the edge and reads as attached and floating. `gray-500` is as light as
it goes before the white 10px glyph drops under 3:1 (white on `gray-400` is
~2.5:1); `gray-800` at the other end punched a hole in the saturated fill. The disc, fill and size are untouched
— a squircle for SIMA was built and pulled, and a glyph *inside* the fill is
the printed-number problem again (no ink survives all five levels). The badge
rides only the ~15 spatially spread SIMA markers, so it does not pile up in the
basin. It is a child of `__dot`, so it scales and lifts with the selected disc.
Network is also named on the card, in Capas -> Fuente, and in the marker's
`aria-label` — the badge is not the only channel.

**Pure `color` is the legend key only; every data surface uses the calmed
`getMarkerFill`.** A marker's fill is that level's `color` nudged ~25% toward
its own `ink` (`getMarkerFill`, `MARKER_INK_MIX`), enough to take the electric
edge off IMECA yellow and green on the pale basemap without shifting hue.
Extrem. has `ink === color` and comes through untouched. The **time-scrubber
context strip** (§5) is the same calmed fill, at `fillOpacity 0.68` — it reads
as "the map's discs, small". The legend swatch keeps the pure `color` with a
1px `ink` inset hairline (so a pale fill holds its edge), so a disc still reads
back to its row. A resting disc
is then painted at reduced alpha (in `globals.css`, not in the mix) so that
where discs pile up in the basin the overlap reads as denser colour rather than
one disc masking another — **75% for a SIMA disc, 65% for a citizen one**
(`--marker-rest-alpha`, part of the network-weight split in §5).
**Every disc is matte, no gloss** — resting and selected
alike. A field-wide highlight read as candy in the packed basin; the rim and
double shadow carry "object on the map" without it, and the flat finish matches
the app's glass panels. The **selected** disc leads by size (§5), an opaque
fill, a taller lift and the pulse, nothing painted on top. The marker
**rim hairline** (`--marker-edge`) and the selected-marker **pulse halo** split: the
rim takes `ink` (it must hold an edge over map imagery), the halo takes
`color` (a large soft fill wants full chroma). The government (SIMA) badge (see
above) sits outside this system entirely: its own `gray-500` ground, no
air-quality hue.

On a chart, a **dot that stands for a single reading** takes the official
`color` for its body and that level's `ink` for its 1px ring, so a pale yellow
or green dot still holds an edge on the white plot. The sparkline's latest-hour
dot and its hover dot both follow this — but never both at once: the latest-hour
dot is hidden for as long as a hover point is active. The headline above already
swaps from "now" to that hour's reading on hover, so leaving both dots up would
put two points in focus on the same chart; only one dot claims the chart at a
time, matching the headline's own focus. The **quality headline** in the
estación card is `ink` (colored text, ≥3:1 — it is bold 24–30px, so the
large-text floor applies, not the stricter 4.5:1 body-text one) — the status
word is the card's most important element and stays colored, not neutral. The
**line and the crosshair stay neutral** (`SPARKLINE_COLOR`): the path is one
series, the crosshair is a position cue, only the point is a value.

The sparkline's **IMECA threshold lines** (`IMECA_THRESHOLDS`, dashed, 55%) are
drawn in each opening level's `ink` — a 1px guide needs the darkened hue to be
visible at all.

## 4. Typography

Inter throughout. Sizes are deliberately small and the scale is short.

| Role | Classes |
|---|---|
| Quality word (estación card, desktop + mobile sheet) | `text-2xl font-bold`, in the band `ink` (§3). The mobile peek row uses the same size |
| Panel / dialog title | `text-base font-medium text-gray-700` (dialog: `text-gray-800`) |
| Card sub-title | `text-sm font-semibold text-gray-800` |
| Body (chrome: panels, cards, sheets) | `text-sm leading-relaxed text-gray-500` |
| Body (dialog paragraphs) | `text-[15px] leading-relaxed text-gray-600` — a dialog is a reading surface, not chrome; `gray-500` at 14px sits on the 4.5:1 line and reads tired across a paragraph. `gray-600` (~7:1) at 15px is the comfortable floor. |
| Dialog inline link (`DialogLink`) | `font-medium text-gray-700` + `underline underline-offset-2`, `hover:text-gray-900`. A link in prose must out-weigh the prose or it is just underlined body text. |
| Row label | `text-sm font-medium` |
| Chip value | `text-[13px] font-medium text-gray-700` |
| Nav label | `text-sm font-medium`, current page `font-semibold` |
| Chip quiet label | `text-[13px] text-gray-500` |
| Eyebrow label | `text-xs font-medium uppercase leading-none tracking-wide text-gray-400` |
| Meta, counts | `text-xs text-gray-500` |
| Micro numbers, axis | `text-[11px] leading-none` / `text-[10px] font-medium` |
| Pending badge (desktop) | `text-[10px] font-semibold uppercase tracking-wide`; mobile swaps it for a `h-1.5 w-1.5` dot |
| Footer legal | `text-xs text-gray-400` |

Rules:
- `tracking-wide` is used **only** with `uppercase`. Nothing else gets tracking.
- `leading-none` on labels and single-line meta; `leading-relaxed` on any
  paragraph of Spanish copy.
- Weights in play: `font-medium` (500), `font-semibold` (600), `font-bold`
  (700). No `font-light`, no `font-extrabold`.
- Truncate rather than wrap in chrome: `min-w-0 flex-1 truncate`, and
  `whitespace-nowrap` on chips and buttons that must hold their width.
- The "label · summary" idiom is the house pattern for a collapsed header:
  bold label, then `· ` plus a muted summary.

### Copy
Spanish, sentence case, no em-dashes anywhere in user-facing text. Use commas
or periods. Section names are capitalized as products: "Capas", "Calidad del
Aire", "Sensores Ciudadanos", "Estaciones de Gobierno".

## 5. Components

### Radius scale
| Radius | Where |
|---|---|
| `rounded-full` | nav pills, dots, tooltips-as-chips, grabber |
| `rounded-3xl` (24px) | dialogs, bottom sheets (`rounded-t-3xl`) |
| `rounded-2xl` (16px) | floating panels, cards, grouped lists |
| `rounded-xl` (12px) | chips, FABs, buttons, nested cards, inline blocks |
| `rounded-lg` (8px) | icon buttons, focus targets on bare links/logos |
| `4px` (inline style) | the layer checkbox |

Bigger surface, bigger radius. Never mix two radii on nested containers by more
than one step.

### Icon sizes
Lucide icons, one of a small set of sizes. Match the row you are in rather than
picking a new value.

| Size | Where |
|---|---|
| `h-5 w-5` (20px) | nav-pill icons, the two mobile FAB glyphs (Navigation, Layers) |
| `h-4 w-4` (16px) | icon-button glyphs, the chevron in a list row's trailing rail |
| `h-3.5 w-3.5` (14px) | inline metadata icons in the sensor card (source glyph, copy / check) |

### The map: markers only
No painted layer of any kind. Every attempt at one — clustering, density
heatmap, IDW gradient, IDW contour bands, an IQAir-style flat tint — was built
and pulled; the map is the basemap plus one DOM marker per reporting sensor.
Don't re-propose a painted surface without the user asking.

**Markers** (`.sensor-marker`, `createMarker` in `lib/air-quality.ts`). One
disc per visible sensor, flat at every zoom, sized **by network**: 27px for a
SIMA reference station, 24px for a citizen (PurpleAir) sensor. Sizing *by zoom*
was tried and taken back out (a disc that shrank at metro zoom read as basemap
furniture); a flat constant is a different lever, loosening the basin pile-up
while the rim + 2px white ring + double shadow hold the sensor read that a bare
shrunk disc lost. 32 was the first flat value; 27 with the heavier white ring
and a matte fill packs the basin as a field of countable dots rather than one
glossy mass. The citizen disc then drops to 24px and a lower rest alpha (below)
because PurpleAir is uncorrected and not methodologically comparable to the
calibrated network (methodology doc) — the reference field is the spine, the
citizen field the texture. It keys on provenance, never on the reading, so it
does not bias the render. Fill is the level's `color` nudged ~25% toward its
`ink` (`getMarkerFill`), painted at **75% alpha at rest for SIMA, 65% for
citizen** (`--marker-rest-alpha`; solid when selected), **matte**, to calm IMECA
yellow/green and let overlaps read as density. No disc has a gloss, resting or
selected; the dimensional cue is the rim + double shadow alone, so markers stay
the same flat design system as the panels around them. Every marker is a real `<button>` with
an `aria-label` carrying its full reading; focus ring is the solid `2px #111827`
outline, not the house ring, because the house ring vanishes over map imagery.
No clustering.

**Every marker is a disc, regardless of source** — the network shows in *weight
and marks*, never in *shape*. A squircle for SIMA stations
(shape coding the network, AirNow-style) was built and pulled — "the squares
don't look good." So the government network reads apart three ways, all on the
same circle: the bigger 27px disc at fuller 75% alpha (vs citizen 24px / 65%),
a **corner badge** (`.sensor-marker__badge`, §3 Air-quality scale) — the
`Landmark` glyph on a `gray-500` disc pinned to the upper-right, overlapping the
edge — and a resting `z-index`. Nothing goes on the fill — a glyph inside the
disc is the printed-number problem again. The badge is safe on the packed basin
because it rides only the ~15 spatially spread SIMA stations. **SIMA discs also
carry a resting `z-index: 3`** (`.sensor-marker--sima`, `globals.css`) so a
reference-grade station always paints over the citizen field in an overlap; it stays under
`ACTIVE_MARKER_Z` (6) and `HOVER_MARKER_Z` (7), so a selected or hovered
citizen disc still lifts above it. Source is also still a Capas-panel concern
(the Fuente filter rows), is named on the estación card, and now rides in every
marker's `aria-label`; a "N sensores, ciudadanos y gobierno" line in the Capas
header was tried and pulled, so the collapsed summary stays the plain filter
state ("Todos los sensores" / "N de M sensores").

The **active** marker — the selected sensor, else the default station the card
shows at rest (`DEFAULT_SENSOR_ID` = `"CE"`, SIMA Obispado) — leads by **size
and pulse**: `--dot-scale: 1.25` (past the field's `1.12` hover), an opaque fill
(the field rests translucent — 75% SIMA, 65% citizen), the ink + 2px white edge every disc carries, a
slightly taller lift, and the pulsing halo in its own air-quality `color`.
Nothing is painted on top: no number, no gloss, no accent ring, no core.

**Grey no-data state** (`.sensor-marker--nodata`). A citizen sensor with no
reading for the frame on screen (live, or a scrubbed hour) drops out — we hold
no history of where a moved/removed citizen sensor was, so a phantom dot would
misrepresent coverage. A **SIMA station** stays: the 16 are fixed, spread, and
their absence is meaningful, so it renders as a muted grey disc (fill at 55%
not 75%, a flat lift, the `Landmark` badge kept, `aria-label` "…, sin lectura").
It recedes behind the live coloured field but the network's shape holds. A
selected grey station does **not** pulse — the halo means "live reading right
now", which it has none of.

**No marker prints its reading.** The exact number lives on the estación card
(always on screen, with its word label) and in every marker's `aria-label`;
the marker itself is a locator plus a severity colour, the IQAir / Google AQI
model (AirNow and PurpleAir print a number on every pin, a philosophy this map
does not follow). Printing the selected value on the disc was tried several
ways — a white core, a dark centre lens, a heavy `-webkit-text-stroke`,
near-black straight on the fill — and each read as a sticker or vibrated
against the saturated mid-tones. Every marker is a bare matte disc.

**Card.** At rest the desktop right column / mobile bottom sheet shows the
**default station's** card (`DEFAULT_SENSOR_ID` = Obispado). Selecting a marker
swaps it to that sensor and adds an **X** to close back to the default. There is
no metro-wide / median fallback — a named station's own reading only (Editorial
invariant). The card carries the name, reading, 48h sparkline, coordinates and
health recs — full spec in §5 Estación card.

### Estación card

### Time scrubber
`TimeScrubber` — **desktop only** (`hidden md:flex`), the Glass panel recipe as
a bar docked bottom-right (`absolute bottom-12 right-6 z-20`), `w-[min(90vw,40rem)]`,
`items-center gap-3 px-4 py-3`. Repaints the whole marker field at a chosen
hour (`paintFrame` mutates markers in place, no rebuild) over a **rolling
42-day window** (`/api/field-history`, `WINDOW_DAYS`); a `TimeScrubberSkeleton`
of the same shell holds the slot while that window loads.

Left to right:
- **Play** button (circle, `Icon button` family) — steps hourly to the end,
  `700 / speed` ms. Then a **speed** toggle cycling `1× / 2× / 4×` (`text-[12px]
  font-semibold tabular-nums text-gray-500`). Both hidden under
  `prefers-reduced-motion`.
- **Context strip** — one bar per hour, or per day past ~3 weeks (so 1500
  hourly slivers don't mush), in that value's `getMarkerFill` colour at
  `fillOpacity 0.68` (the calmed marker fill — pure NOM `color` stays on the
  legend key only). Height ∝ value / window-max (floored at 15 µg/m³), `H` 30px.
  White midnight dividers; sparse date labels above (`text-[10px] text-gray-500`,
  ≤7). Memoised on the series, **not** the scrub position — dragging must not
  re-render ~1500 `<rect>`s per frame.
- **Playhead** — the range input lies transparent over the strip
  (`.time-scrubber`, `globals.css`); thumb is a 3px dark bar with a 1.5px white
  casing so it holds an edge over any bar colour. `aria-label="Hora del mapa"`,
  `aria-valuetext` = the hour as prose ("1 jul, 3:00 PM") or "En vivo".
- **Readout** — stacked label over value, right-aligned, `leading-tight`.
  **Live**: `Actualizado` (`text-[10px] text-gray-400`) over the freshness time
  (`text-[13px] font-medium text-gray-700`), preceded by `FreshnessDot` only
  when `delayed` / `stale`. **Scrubbed**: the day over the hour, plus an
  **Ahora** button (`Secondary button`-ish text, `text-[13px] font-medium
  text-gray-500`) that returns to live.

State travels as `?t=<YYYY-MM-DDTHH>` (`lib/map-url-state.ts`), live-synced.
**Mobile has no scrubber control**, but honours `?t=` **read-only**: a shared
link repaints the field and shows a top banner (`absolute inset-x-4 top-4
z-[45]`, blue-accented glass) — `Mostrando <hora>` + a `Ver en vivo` button.
That's the only way in and the only way out on a phone.

### Bottom sheet
There are two, and they behave differently.

**Capas / legend disclosure sheets.** Shell: `fixed left-0 right-0 bottom-0 flex
max-h-[85svh] flex-col overflow-hidden rounded-t-3xl bg-white
shadow-[0_-4px_20px_rgba(0,0,0,0.08)] md:hidden`, shown / hidden with `transform:
translateY(0 | 100%)`. The height cap and `overflow-hidden` sit on the **shell**,
not the body — same split as the Dialog shell below. Anchor at `bottom-0` so
`translateY(100%)` fully clears the viewport; a sheet anchored above the nav
(`bottom: calc(3.5rem + …)`) would stay on screen when "closed" and would need
`pointer-events-none` while shut or it eats touches for whatever is behind it.
Grabber `mx-auto mb-3 h-1 w-10 rounded-full bg-gray-300/60` in a `flex-shrink-0
cursor-grab select-none` header (grabber area `pb-4 pt-3`).

**Resting estación sheet.** `fixed left-0 right-0 z-[40]`, anchored `bottom:
calc(3.5rem + env(safe-area-inset-bottom))` (clear of the nav), a fixed
`height: 62dvh`, and **2-state** — `peek` / `mid` — driven by a *partial*
transform, `translateY(calc(100% - 5.5rem))` at `peek` (grabber + the pinned
title row showing, see §5 Estación card) and `translateY(0)` at `mid`. It sits
**fully off-screen** (`translateY(100%)`) only when there is no `cardSubject`
(Obispado filtered out); otherwise it peeks the default station at rest.
Tapping a marker swaps the subject without changing the height (stays at
`peek` from `peek`, stays at `mid` from `mid`, see §5 Estación card); the
grabber-row tap toggles `peek` ↔ `mid`; the X / backdrop / map tap run
`closeCard()` back to `peek` on the default. It is glass at `peek`
(`bg-white/80 backdrop-blur-md border-t border-white/60`) and opaque `bg-white`
at `mid`. Grabber block `flex-shrink-0 cursor-pointer select-none px-5 pt-3 pb-3`
— the whole area is the peek↔mid toggle (`handleSheetTap`) and carries the
pinned station name; the **X** close (only when a marker is picked) is a
trailing `stopPropagation` button in that row. The mobile Capas / legend
buttons sit 1rem above this sheet's peek edge (`+ 6.5rem`, §1).

Body (both sheets): **a plain block** — `min-h-0 flex-1 overflow-y-auto
overscroll-contain px-5 pb-8` (the resting sheet adds `pt-2`) — never `flex
flex-col`. Same rule as the Dialog body. The body's one child is often a grouped
card with `overflow-hidden` (its rounded corners); as a flex item that resolves
to `min-height: 0`, so a flex-column body shrinks the card to its own height and
the card clips its content away instead of overflowing and scrolling here.

### Dialog
Native `<dialog>` via `DialogShell` / `InfoDialog`. Shell:
`flex max-h-[85svh] w-[85%] max-w-md flex-col overflow-hidden rounded-3xl
border border-gray-200 bg-white p-8 shadow-xl`. Opaque, not glass, for the
reason in §3 Surfaces: dialog body copy could not hold 4.5:1 over a map that
shows through. The scrim carries the depth (`::backdrop`, `rgb(0 0 0 / 0.4)` +
`blur(6px)` — a light blur; 12px made the panel/map seam a hard restless edge),
so the panel does not need to. Header never scrolls (`flex-shrink-0`), body does
(`min-h-0 flex-1 overflow-y-auto overscroll-contain`). Escape routes through
`onCancel` into React state; outside-click requires both mousedown and click to
land outside.

**Dialog copy is stronger than chrome copy** (§4): paragraphs are
`text-[15px] leading-relaxed text-gray-600`, an `InfoSection` body ground is
opaque `bg-gray-50`, and `DialogLink` is `font-medium text-gray-700`
(`hover:text-gray-900`). The dialog is the reading surface, so it does not
borrow chrome's `text-sm text-gray-500`.

### Tooltip

Two kinds, split by **where they sit**, not by how much they hold:

- **Hint tooltip** (an icon's label, a transient hint over page content): dark,
  transient, single line. `pointer-events-none ... rounded-lg bg-gray-900 px-3
  py-1.5 text-xs text-white shadow-sm`. It floats over arbitrary page content
  and has to read as system feedback, not a surface, so it is dark with no
  border. This is the one place the `bg-gray-900` tooltip token holds. No live
  case right now: the nav's pending pills used to carry one and now show a
  standing badge / dot instead (§5 Nav pill). Keep the recipe for the next
  transient hint that genuinely floats over content.
- **Chart tooltip** (anything anchored inside a chart's plot area, whether it is
  a multi-row hover card or a single-line timestamp label): light, near-solid.
  `bg-white/95`, `border border-black/[0.08]`, `backdrop-blur-[6px]`,
  `shadow-[0_6px_24px_rgba(0,0,0,0.1)]`, dark text (`text-gray-700`, values in
  `font-medium`). Radius follows size: `rounded-xl` for a padded multi-row card
  (`dias-insalubres`, padding `16px 22px`), `rounded-lg` for a single-line pill
  (the `Sparkline` hover in `mapa-sensors.tsx`). Not the glass recipe: readouts
  have to stay crisp, so contrast beats transparency the same way it does in a
  dialog. The hairline is `black/[0.08]`, not `white/60`, because `white/60` is
  invisible on a near-opaque white ground; the shadow does the lifting that a
  dark fill used to.

A chart tooltip stays light even when it carries only a label: one rule per
surface beats a per-tooltip judgement call that the code keeps re-litigating.

**Placement.** A chart tooltip tracks the cursor on the x axis only and is
pinned to a fixed y just inside the plot area's top edge (`top: 0`,
`translate(-50%, 6px)`), so it holds still while the cursor scrubs instead of
riding the line. It never crosses the plot area's top edge: on the sensor card
the PM2.5 headline sits directly above, and a tooltip over that edge covers the
reading the hover is meant to explain. Pad the value domain (here 15%) so the
line's peak never reaches the pinned band. Clamp the x offset so the box stays
inside the card (`clamp(70px, <x>%, calc(100% - 70px))`). This is the
Vercel / Stripe / GitHub-analytics convention; a tooltip that follows the
pointer in both axes and flips to the left near the right edge is the
*pointer-anchored* pattern, for hovers that snap to the mouse rather than to a
data point, and is not used here.

### Focus
One ring everywhere:
```
focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-gray-900/15
```
Add `focus-visible:ring-inset` on full-bleed rows so the ring is not clipped.

### Motion
| Effect | Value |
|---|---|
| Color / background | `transition-colors` unqualified (150ms) for incidental tint; `duration-200` on anything the user directly drives (pills, FABs, icon buttons, chevrons); `duration-300` on scrims and full-panel fades only |
| Chevron disclosure | `transition-transform duration-200` + `rotate-90` when open (`-rotate-90` for a panel that opens upward) |
| Scrim | `transition-opacity duration-300` |
| Disclosure body | `.disclosure-in`, 180ms ease-out, fade + `translateY(-4px)`; `.disclosure-in-up` is the mirror (`translateY(4px)`) for a panel that opens upward |
| Dialog | `dialog-in` 160ms ease-out, fade + `scale(0.97)`; backdrop fades with it |
| Marker hover | `transform: scale(1.12)` on the dot, 0.15s ease |
| Marker selected | `marker-pulse` 2.4s ease-out infinite, halo behind the dot |
| Fresh-data dot | `animate-ping` on the green halo only |
| Map camera | one opening `flyTo`, `OPENING_MOVE_MS` (4500ms), no custom easing, from zoom 8 to the metro field centred on the default station at zoom **11** (`13` for a `?sensor=` link, `10.5` `OPENING_CENTER` if no station); `jumpTo` under reduced motion |

Chevrons rotate, they are never swapped for a different glyph, and they rotate
**toward the content they reveal**: down for a panel that opens downward, up for
one that opens upward. A disclosure anchored to the foot of its column (the
desktop air-quality legend) keeps its trigger row on the bottom edge and
unfolds the body into the gap above it, so the row you just clicked holds
still; use `flex-col-reverse` to paint the trigger last while keeping it first
in the DOM, so tab and screen-reader order stay trigger-then-body. Disclosures
animate **in only**; an exit animation would keep controls in the tab order
after they are visually gone.

**Map camera.** One move: the opening `flyTo`. The map is constructed at zoom 8
over the metro (`OPENING_CENTER`) and a single `flyTo` settles it in **centred
on the default station at zoom 11** — the metro field with that station's pulse
in frame; knowing which station the card speaks for matters, going right to it
doesn't. A shared `?sensor=` link instead flies in close (**zoom 13**) — that
link *is* about the station. `10.5` at `OPENING_CENTER` if there's no station.
Runs once (`didOpeningFlyRef`). No locate-me: this is an open-data map of the
airshed, not a personal "air near me" readout.

Use `flyTo`, not `easeTo`, for any move over ~2 zoom levels: `flyTo` runs the
van Wijk-Nüij curve that holds *perceived* zoom speed constant, where `easeTo`
interpolates the zoom number linearly and the view accelerates into the stop,
which reads as slow-then-lunge. Do not hand `flyTo` a custom `easing`; its curve
is already tuned. The 4.5s duration replaced 3s, which over five zoom levels
read as a lunge. Padding is set instantly (not interpolated alongside the fly,
which looked like the map veering sideways). `essential: true` keeps the move
from being dropped when the tab is backgrounded, so it is paired with a
`prefersReducedMotion()` check that swaps the whole move for a `jumpTo` to the
same framing. `easeTo` is only for small nudges, a level or two, a position or
bearing tweak.

Every looping animation has a reduced-motion escape: either
`motion-reduce:animate-none` in Tailwind, or a
`@media (prefers-reduced-motion: reduce)` block in `globals.css` that stops the
animation and leaves a static low opacity. The non-looping exception, the
opening camera, gets its escape in JS (`jumpTo`) for the reason above.

## 6. Accessibility invariants

These were fixed deliberately. Preserve them in anything new.

- Text hits 4.5:1, non-text controls hit 3:1. That is why the gray tokens above
  are the values they are.
- Color is never the only channel. The freshness dot is backed by a real
  timestamp. The map markers carry no printed number, but the selected sensor's
  reading is on the estación card with its word label ("Mala"), the legend maps
  every colour to its label, and every marker's `aria-label` carries the full
  reading. If markers ever regain a value channel it must not be colour alone.
  A grey no-data SIMA marker announces "…, sin lectura"; the card shows
  "No disponible" as text, not a bare "—".
- Every icon-only control has `aria-label`; decorative icons get
  `aria-hidden="true"`. The card / sheet **X** is `aria-label="Cerrar"`;
  Escape closes the card (guarded so an open `<dialog>` gets Escape first).
- The scrubber range input carries `aria-valuetext` (the hour as prose, or
  "En vivo") — the raw slider index announces as a meaningless number otherwise.
- Disclosures wire `aria-expanded` + `aria-controls`, and the panel stays
  mounted with `hidden` so `aria-controls` always resolves.
- Async status is announced through a separate `role="status"` node
  (`sr-only`), not by mutating a disabled button's label.
- Messages persist until dismissed. Nothing important disappears on a timer.
- External links carry `<span className="sr-only"> (abre en una nueva pestaña)</span>`.
- Transparency has an escape: `prefers-reduced-transparency: reduce` is handled
  globally in `globals.css` (see §3 Surfaces). Every glass surface goes opaque;
  the map-marker white ring and drop shadow already keep markers separable
  without it.
- **Forced colors (Windows High Contrast) is not yet handled, and is the next
  real gap.** The glass edges (`border-white/60`), the marker white ring, and
  the layer checkbox's inline hex all vanish when the OS replaces the palette.
  When it is addressed: do it in one `@media (forced-colors: active)` pass over
  every token, lean on system colors (`Canvas`, `CanvasText`, `ButtonBorder`,
  `Highlight`), and keep `forced-color-adjust: none` only where an air-quality
  fill genuinely must survive (the legend swatches, the markers). A half pass is
  worse than none, same rule as the dark theme in §3.

## 7. Quick checklist for a new component

1. Floating over the map? Glass recipe, `rounded-2xl`, on the 24px surface rail.
   Reduced-transparency is handled globally, add nothing per component.
2. Header text? `px-5 pt-4 pb-3`, `text-base font-medium text-gray-700`.
3. Body copy? `text-sm leading-relaxed text-gray-500`.
4. Eyebrow? `text-xs font-medium uppercase leading-none tracking-wide text-gray-400`.
5. Rows? `py-3.5`, `border-t border-gray-100`, `hover:bg-gray-100/70`.
6. Any focusable element? The `ring-2 ring-gray-900/15` ring, no exceptions.
7. Any animation? A reduced-motion fallback.
8. Any air-quality color? From `lib/air-quality.ts` (see Constants index).
9. Any Spanish copy? Sentence case, no em-dashes.
10. Reusing a named value (padding const, sensor id, camera setting)? Import it,
    do not re-type the literal. If it is a third copy of an inline value, lift it
    to a const.
11. Map state that should be shareable (a selection, a filter, a scrubbed hour)?
    Route it through `lib/map-url-state.ts` — History API, not the Next router.
12. Reporting an air-quality value? It is a **named station's** reading, never a
    metro-wide characterization (Editorial invariant).
13. Verify with `pnpm exec tsc --noEmit` then `pnpm build`. `pnpm lint` is
    currently broken in this repo, so it is not the gate. `pnpm build` always
    logs one `DYNAMIC_SERVER_USAGE` warning on the home route; that one is
    expected.
