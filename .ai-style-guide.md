# Aire Claro, AI Style Guide

The visual contract. Read it before adding a **new component** or changing a
**token**; a one-off tweak to an existing component doesn't need a full read.
For a new interactive control, copy the nearest approved component rather
than inventing a value. **No component library** (shadcn/ui was removed
2026-09-19, see memory) — everything is hand-built to the tokens/recipes
below, plain Tailwind on plain HTML elements.

Approved surfaces: the **Navbar** (`components/navbar/`), and the map's **Capas**
panel, **Actualizado** badge, **info dialogs** and **estación card**
(`components/mapa/mapa-sensors.tsx`).

Tailwind (`tailwind.config.ts`) extends stock with three named panel widths and
three CSS-variable tokens (`background`, `foreground`, `border` →
`hsl(var(--…))` in `app/globals.css`) — trimmed 2026-09-19 from shadcn/ui's
original ~20-variable bridge down to just what's actually consumed (`body`'s
base colors, a global border-color reset). Radius classes are stock
Tailwind, no overrides. The air-quality scale is **not** a token — it lives in
`lib/air-quality.ts`. Font is **Inter** (`next/font/google`, latin +
latin-ext, `display: swap`), on `<body>`.

**Readings are per-station.** Every reading on screen is tied to a named
station, or is a *coverage* statement ("15 estaciones · 160 sensores
reportando"). The field of coloured discs is the "at a glance".

**The app is light-only.** No dark theme, no `dark:` variant anywhere. A real
dark theme is its own project with its own pass over every token; don't add one
ad hoc.

## 1. Layout and containers

### Breakpoints
`md:` (768px) is the main desktop switch and carries almost everything; `sm:`
(640px) and `lg:` (1024px) handle a few container/footer cases. No `xl:` /
`2xl:`, only the `max-w-7xl` content cap. Reach for `md:` first.

### Page shell
| Element | Classes |
|---|---|
| Root wrapper | `flex min-h-svh flex-col` |
| `<main>` | `w-full flex-grow overflow-y-auto bg-gray-50` |
| Header height | `h-header` (`--header-h`: `72px`, `76px` at `lg`) |
| Map viewport | `h-below-header` |

Never restate `72px` / `76px` or write `h-[calc(100svh-72px)]`; use the utilities.

### The two rails
Every floating element sits on one of two optical rails:
- **Surface rail, 24px** (`left-6` / `right-6`): where a panel's *edge* lands.
- **Text rail, 44px**: where a panel's *text* lands (24px surface + 20px `px-5`).

The desktop header is asymmetric on purpose (`pl-11 pr-6`): the bare logo has no
surface, so it's pushed to the 44px text rail to line up with "Capas" below it.
Artwork that leads with a curve crosses its rail 1–3px for optical level (the
desktop logo carries `-ml-0.5`); a text label sits on the rail exactly.

### Floating-panel anchors
| Anchor | Classes |
|---|---|
| Capas column | `absolute left-4 top-4 md:bottom-14 md:left-6 md:top-6` (legend pill pinned at foot with `md:mt-auto`). Freshness pill + Mi zona button sit at the foot of the right card column |
| Right card column | `absolute right-6 top-6 md:bottom-14` (card only; `flex-1` wrapper fills the column height) |
| Mobile Capas button | `fixed right-6` + `bottom: calc(env(safe-area-inset-bottom) + 6.5rem)` (1rem above the 5.5rem peek sheet) |

`bottom-14` (56px) is the working margin (raised from 40px on 2026-10-18 so
the right column's pills clear the map's attribution with room); both
columns share it so their feet line up.

Overlay containers are `pointer-events-none`; each interactive child re-enables
with `pointer-events-auto` so the map stays draggable through the gaps.

### Surfaces
| Role | Value |
|---|---|

| Sheet scrim | `bg-black/20` |
| Opaque sheet | `bg-white` + `shadow-[0_-4px_20px_rgba(0,0,0,0.08)]` |
| Peek-state sheet | `bg-white/80 backdrop-blur-md border-t border-white/60` |

| Inline detail block | `bg-gray-50` |

Translucency for floating chrome, **opaque paper for reading surfaces**: every
floating map panel and chip is `.glass`; dialogs are opaque white on a
`gray-200` hairline (at `bg-white/90` the map bled through and pushed dialog
body text under 4.5:1 — the scrim carries the float instead).

`prefers-reduced-transparency: reduce` (`globals.css`) drops the blur and takes
`.glass` plus the raw near-white utilities to solid `#fff`. Scrims keep their
translucency. Nothing per-component is needed — use `.glass`.

### Text
| Role | Token |
|---|---|
| Primary heading / value | `text-gray-800` |
| Panel title, body strong | `text-gray-700` |
| Secondary body (chrome) | `text-gray-500` |
| Dialog paragraphs | `text-gray-600` (a dialog is a reading surface; `gray-500` reads tired across a paragraph) |
| Nav resting label | `text-gray-600` (4.5:1 floor, never `gray-400`) |
| Tertiary / eyebrow | `text-gray-400` (uppercase micro-labels, icons) |
| Counts, row summaries | `text-gray-500` at `text-xs` (they carry data, clear 4.5:1) |
| Inverse | `text-white` on `bg-gray-900` |

**Settled contrast rules, don't undo:**
- Unselected nav label `gray-600` (not `gray-400`, 2.5:1 fails).
- Dialog close X `gray-500` (needs 3:1 as the only exit).
- Counts / summaries `gray-500`. `gray-300` is furniture only (grabber, em-less
  placeholder dash).
- The Actualizado chip's *value* is `font-medium text-gray-700`; `gray-500` is
  only the quiet half, never a chip's only text.

### Air-quality scale
Never hardcode. Import from `lib/air-quality.ts`.

Two tokens per level. `color` is the official NOM-172 hue, for anything with
**area** (fills, legend swatches, the pulse halo). `ink` is
that hue darkened only as far as it needs to clear **3:1 on white**, for
everything on a light ground that is **not** a fill (bold quality headline,
hairlines, 1px rings, the marker rim). Nothing using `ink` is body text, so 3:1
is the correct floor.

| Level | ≤ | `color` (fills) | `ink` (≥3:1, hairlines/bold) |
|---|---|---|---|
| Buena | 15 | `#00e400` | `#00a400` |
| Aceptable | 25 | `#ffff00` | `#ad8900` (gold — no honest dark yellow at any floor) |
| Mala | 79 | `#ff7e00` | `#de6e00` |
| Muy mala | 130 | `#ff0000` | `#ff0000` |
| Extremadamente mala | ∞ | `#8f3f97` | `#8f3f97` |

- **Pure `color` is the legend key only; every data surface uses the calmed
  mix** — `color` nudged ~25% toward `ink` (`getMarkerFill` / `getMarkerFillHex`,
  `MARKER_INK_MIX`). If the marker field reads too electric, raise
  `MARKER_INK_MIX`, don't re-darken `ink`.
- **A chart dot for a single reading** takes `color` for its body and that
  level's `ink` for its 1px ring. (For `/datos` charts when they land — the map
  card no longer has a trend chart.)
- **The estación-card quality headline** is `ink` (bold coloured text) — the
  status word is the card's most important element and stays coloured.
- No valid reading (`isValidPM25`, dropped at read time) → nothing for a
  citizen sensor; a SIMA station renders grey (`nodata`, §5).
- **Pollutant is PM2.5, stated not filtered.** The map shows one pollutant by
  choice, not limitation. It appears on the reading (`µg/m³ PM2.5`) and as the
  `PM2.5 · µg/m³` line in the expanded legend, which carries a small `Info`
  button → one-paragraph `InfoDialog` ("qué es PM2.5"). **Not** a Capas filter
  row and **no** "PM10 / no disponible" rows anywhere.

  `whitespace-nowrap` on chips / buttons that must hold width.
- "label · summary" is the house pattern for a collapsed header: bold label,
  then `· ` + muted summary.

## 5. Components

### No component library
Removed entirely 2026-09-19 (shadcn/ui — Radix + `cva`, `components/ui/`) —
explicit call: less lock-in, direct control over markup/behavior, matching
the same reasoning that dropped Recharts a day earlier. Interactive pieces
(loading skeletons, the falta-de-información tooltip, the
PM2.5 daily table) are now plain Tailwind on plain HTML elements, each
hand-built to this guide's tokens/recipes directly. `cn()` (`lib/utils.ts`,
clsx + tailwind-merge) stays — it's a generic class-merge helper, not
component-library machinery — but nothing imports Radix or `cva` anymore.
Deep-dive/what-changed: see memory.

Consequence for a new interactive control: there's no primitive to reach
for. Hand-build it to this guide's tokens (the neutral 2px focus ring at
15% ink, the §5 radius scale, the recipes below) the same way the
skeletons, and chart tooltips are built — or copy the nearest existing
pattern rather than inventing a new one.

**Charts are hand-rolled SVG, no charting library** (Recharts was removed
2026-09-19; see memory). Mark specs follow the dataviz skill directly: bars
capped at 24px with the leftover band as air, no border on a mark (color +
a surface gap separate bars/segments instead), rounded only at a bar's
outer tip and square at the baseline, solid recessive gridlines, dashed
reserved for threshold reference lines. Shared geometry (`niceTicks`,
`roundedRectPath`, `tooltipPositionStyle`) lives in
`components/datos/svg-chart-utils.ts`. Air-quality series pull from
`lib/air-quality.ts`; the `/datos` charts' own good/bad pair (días
insalubres, cobertura de estaciones, promedio anual) lives in
`lib/datos-colors.ts` (`COLOR_SALUDABLE` / `COLOR_INSALUBRE`) — a bespoke
pastel green/red, pixel-matched to a user-supplied reference rather than the
dataviz skill's validated palette (that palette was tried and explicitly
overridden; see memory).

**The map keeps its bespoke interaction components on purpose** — the info
popups on the platform `<dialog>` (top layer, native focus trap), the
2-state mobile sheet, the legend / health-recs. It was never shadcn-based
to begin with, so this session's removal didn't touch it.

### The map
The marker field is one MapLibre GL **circle layer** (`FIELD_LAYER`), a `symbol`
text layer for the printed numbers (`FIELD_LABEL_LAYER`), a `symbol` layer for
the SIMA badges (`SIMA_BADGE_LAYER`), and one DOM `Marker` for the selected
station. Mechanics — `buildFieldData` / `updateField` / `syncActive` /
`feature-state` / camera — are in `docs/architecture.md`.

This section splits into two kinds of content, on purpose, because they carry
different weight:

**Mechanics — facts about how the GL renderer/the data actually behave. These don't
go stale when the *look* changes; ignoring one reintroduces a real bug, not
a style regression. Several already shipped broken more than once before
landing here — see [[project_marker_field_rework]] for the full blow-by-blow.**
- `circle-sort-key` = `(isSima ? 1e6 : 0) - lat` decides draw order — latitude
  + provenance only, **never the reading**. This is a "never bias the render"
  invariant (§6 / [[feedback_no_biasing_the_render]]), not a look-and-feel call:
  whichever disc wins an overlap must not correlate with its value.
- **Badge offset must be a flat constant, not zoom-scaled, once size already
  is.** The renderer multiplies `icon-offset` by `icon-size` internally (confirmed
  against the v8 style-spec source) — if both scale with zoom, the offset
  gets scaled down a second time and the badge drifts toward center as the
  map zooms. `FIELD_BADGE_SIZE` interpolates off `fieldRadiusAt`;
  `FIELD_BADGE_OFFSET` stays a flat `["literal",[16,-16]]`.
- **A zoom `interpolate` expression can't nest inside `case`/`match`** — it
  has to be the outermost expression, with any selected-state override
  folded into each stop's own output instead. Nesting it the other way
  doesn't throw; the renderer silently drops the property, so the layer looks like
  it worked while the paint property in question just does nothing. This
  exact mistake has shipped twice in this file (`circle-radius`, then
  `text-opacity`) — check the direction against `FIELD_RADIUS`'s working
  shape before writing a new zoom-interpolated property here.
- **Label visibility is collision-detected** (`text-allow-overlap`/
  `text-ignore-placement` both `false`) — a disc with no room for its label
  goes unlabelled rather than smearing over a neighbor's. `symbol-sort-key`
  reuses the same value-independent sort key the circles draw with, so which
  label wins a collision is never a function of the reading either.
- **No opening camera move.** Collision detection re-runs every frame the
  camera moves, so labels churn in and out through any programmatic fly-in,
  which reads as the numbers "loading in". The map opens directly on its
  resting view, labels visible at once.
- **Never write to `.sensor-marker__dot`'s `.textContent` directly** — the
  SIMA badge is also a child of that element, and `.textContent` silently
  deletes every child node, badge included. The printed number lives in its
  own `.sensor-marker__number` child span.
- **SIMA vs. PurpleAir stays named even though it no longer shows as a size/
  weight split on the map** — SIMA is the calibrated reference network,
  PurpleAir uncorrected, not methodologically comparable
  (`docs/methodology.md`). This is a data-honesty requirement, not a look:
  the distinction has to stay visible somewhere (currently the card, Capas →
  Fuente, and every marker's `aria-label`) whatever the disc styling does.
- **Selected marker size is derived, not a fixed px** — `resizeSelectedMarker`
  reads the same `fieldRadiusAt` stop table `FIELD_RADIUS` is built from,
  re-run on every `zoom` tick (not just on selection change), so it keeps
  leading the field's own size at every zoom rather than just the one it was
  created at.
- **Keyboard:** canvas discs aren't tabbable, so every station is also a
  visually-hidden `<button>` (`a11yStations` / `selectFromList`).
- **No-data:** a citizen sensor with no reading drops out of the source; a
  SIMA station always stays, as a grey disc — the network is fixed, its gaps
  are part of what it means.

**Current visual state — taste, arrived at by trying it on production and
reacting, current as of 2026-09-19. Not a permanent rule: revisit anytime by
asking. Flagged here so a future round doesn't silently re-walk ground
already covered, not to lock it in.**
- Disc: matte, no gloss/bevel/shadow, flat 1.5px white stroke. SIMA and
  citizen are the same size and opacity — the network shows only via the
  `Landmark` corner badge (every SIMA station, grey no-data ones included).
  `circle-opacity` rests at 0.92 for a disc with a reading, 0.5 for a no-data
  SIMA disc.
- Every disc with a reading prints its PM2.5 number, always on — no shape
  behind the digits (a white core, center lens, and text-stroke were each
  tried and read as "a sticker"). Ink is per-level by fill luminance.
  Squircle/shape-coding the network was tried and reverted ("the squares
  don't look good") — every marker is a disc regardless of source.
  A metro-wide/median value anywhere on the card or legend was tried and
  didn't fit this product's stance on not overclaiming past what ~120
  sparse points actually support.
- Selected station: DOM marker (only DOM can carry the CSS pulse halo),
  opaque fill, `--dot-scale: 1.25`, halo in the sensor's own `color`, solid
  `2px #111827` focus outline (the usual translucent house ring disappears
  over map imagery, so this is the one deliberate exception).
- Painted-layer alternatives — clustering, density heatmap, IDW gradient,
  IDW contour bands, IQAir-style flat tint, locate-me/"air near me" — were
  each tried and didn't hold up (the honest reason: ~120 sparse points can't
  support a value surface without overclaiming; IQAir/Apple-style tinting
  needs a denser model this project doesn't have). Worth knowing that
  history before re-trying one, not off the table forever.

### Bottom sheet
Two, behaving differently.

**Capas / legend disclosure sheets.** Shell: `fixed left-0 right-0 bottom-0

### Tooltip
Two kinds, split by **where they sit**:
- **Hint tooltip** (an icon's label, a transient hint over page content): dark,
  transient, single line. `pointer-events-none … rounded-xl bg-gray-900 px-3
  py-1.5 text-xs text-white shadow-sm`. No live case now; keep the recipe.
- **Chart tooltip** (anything anchored inside a plot area): light, near-solid.
  `bg-white/95`, `border border-black/[0.08]`, `backdrop-blur-[6px]`,
  `shadow-[0_6px_24px_rgba(0,0,0,0.1)]`, dark text (`text-gray-700`, values
  `font-medium`). Radius follows size: `rounded-xl` for a padded multi-row card,
  `rounded-xl` for a single-line pill. A chart tooltip stays light even when it
  carries only a label — one rule per surface.

**Placement.** A chart tooltip tracks the cursor on x only, pinned to a fixed y
just inside the plot area's top edge (`top: 0`, `translate(-50%, 6px)`), and
never crosses that edge (the card's PM2.5 headline sits right above it). Pad the
value domain (15%) so the peak never reaches the pinned band; clamp x to
`clamp(70px, <x>%, calc(100% - 70px))`.

### Motion
| Effect | Value |
|---|---|
| Color / background | `transition-colors` (150ms) incidental; `duration-200` on anything the user directly drives; `duration-300` on scrims and full-panel fades |
| Chevron disclosure | `transition-transform duration-200` + `rotate-90` open (`-rotate-90` for a panel opening upward) |
| Scrim | `transition-opacity duration-300` |
| Disclosure body | `.disclosure-in`, 180ms ease-out, fade + `translateY(-4px)`; `.disclosure-in-up` mirrors it |
| Dialog | `dialog-in` 160ms ease-out, fade + `scale(0.97)` |
| Marker hover | `circle-radius` ×1.14 (`feature-state hover`) |
| Marker selected | `marker-pulse` 2.4s ease-out infinite, halo behind the DOM dot |
| Fresh-data dot | `animate-ping` on the green halo only |
| Map camera | no opening move: opens at zoom 11 on the default station (13 for `?sensor=`, 10.5 if none) |

Chevrons rotate toward the content they reveal, never swapped for another glyph.
A disclosure anchored to the foot of its column (the desktop legend) keeps its
trigger on the bottom edge and unfolds upward (`flex-col-reverse` to paint the
trigger last while keeping it first in the DOM). Disclosures animate **in
only** — an exit animation keeps controls in the tab order after they're gone.

**Map camera.** No opening move (removed 2026-10-09 for load speed). Use `flyTo`, not `easeTo`, for any move over ~2 zoom levels — `flyTo` runs the
van Wijk curve that holds *perceived* zoom speed constant; `easeTo` interpolates
the zoom number linearly and reads as slow-then-lunge. Don't pass `flyTo` a
custom `easing`. Padding is set instantly, not interpolated. `essential: true`
pairs with a `prefersReducedMotion()` check that swaps the whole move for a
`jumpTo`. `easeTo` is only for small nudges.

Every looping animation has a reduced-motion escape
(`motion-reduce:animate-none`, or a `prefers-reduced-motion` block in
`globals.css` that stops the loop and leaves a static low opacity).

## 6. Accessibility invariants

Fixed deliberately. Preserve them.

- Text hits 4.5:1, non-text controls hit 3:1 — that's why the gray tokens are
  the values they are.
- **Colour is never the only channel.** The freshness dot is backed by a real
  timestamp. Every marker with a reading also prints its PM2.5 number, the
  selected reading is on the card with its word label, the legend maps every
  colour to its label, and every marker's `aria-label` carries the full
  reading. A grey no-data marker announces "…, no disponible"; the card
  shows "No disponible" as text.
- Every icon-only control has `aria-label`; decorative icons `aria-hidden`. The
  card / sheet X is `aria-label="Cerrar"`; Escape closes the card (guarded so an
  open `<dialog>` gets Escape first).
- Disclosures wire `aria-expanded` + `aria-controls`; the panel stays mounted
  with `hidden` so `aria-controls` always resolves.
- Async status is announced through a separate `role="status"` `sr-only` node,
  not by mutating a disabled button's label.
- Messages persist until dismissed. Nothing important disappears on a timer.
- External links carry `<span className="sr-only"> (abre en una nueva pestaña)</span>`.
- `prefers-reduced-transparency: reduce` is handled globally (§3).
- **Forced colors (Windows High Contrast) is not handled — the next real gap.**
  When addressed: one `@media (forced-colors: active)` pass over every token,
  lean on system colors, `forced-color-adjust: none` only where an air-quality
  fill must survive (legend swatches, markers). A half pass is worse than none.

## 7. Quick checklist for a new component

1. Floating over the map? `.glass`, `rounded-2xl`, on the 24px surface rail.
2. Header text? `px-5 pt-4 pb-3`, `text-base font-medium text-gray-700`.
3. Body copy? `text-sm leading-relaxed text-gray-500`.
4. Eyebrow? `text-xs font-medium uppercase leading-none tracking-wide text-gray-400`.
5. Rows? `py-3.5`, `border-t border-gray-100`, `hover:bg-gray-100/70`.
6. Any focusable element? The `ring-2 ring-gray-900/15` house ring, no exceptions.
7. Any animation? A reduced-motion fallback.
8. Any air-quality colour? From `lib/air-quality.ts`.
9. Any Spanish copy? Sentence case, no em-dashes.
10. Reusing a named value? Import it. Third copy of an inline value → lift to a const.
11. Shareable map state? Route it through `lib/map-url-state.ts` (History API).
12. Verify with `pnpm exec tsc --noEmit` then `pnpm build` (`pnpm lint` is
    broken).
