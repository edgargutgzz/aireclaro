# Aire Claro, AI Style Guide

The visual contract for this app, extracted from the sections that are already
approved and frozen: the **Navbar** (`components/navbar/`), and the map's
**Capas** panel, **Actualizado** badge and **info dialogs**
(`components/mapa/mapa-sensors.tsx`).

Read this before writing any UI. When a new component needs a value that is not
here, copy the nearest approved component rather than inventing a token.

Tailwind runs with a near-default config (`tailwind.config.ts`); the only
extensions are three named panel widths. Everything else below is stock
Tailwind, used consistently. Font is **Inter** (`next/font/google`, latin +
latin-ext, `display: swap`), applied on `<body>`.

## 1. Layout and containers

### Breakpoints
Stock Tailwind, and the set actually in use is short: `md:` (768px) is the
main desktop switch and carries almost everything; `sm:` (640px) and `lg:`
(1024px) handle a few container and footer cases. There is no `xl:` / `2xl:`
in the codebase, only the `max-w-7xl` content cap. Reach for `md:` first; add
another stop only when `md:` genuinely cannot express the change.

| Element | Classes |

### The two rails
The page has two optical rails and every floating element sits on one of them:

- **Surface rail, 24px** (`left-6` / `right-6`): where a panel's *edge* lands.
- **Text rail, 44px**: where a panel's *text* lands (24px surface + 20px `px-5`).

The desktop header is therefore asymmetric on purpose: `pl-11 pr-6`. The bare
logo has no surface of its own, so it is pushed to the 44px text rail to line
up with "Capas" below it; the nav's last pill already reaches the text rail
through its own `px-5`, which holds only as long as that pill is unfilled. The
moment the last pill carries a background it becomes a surface and its edge,
not its label, is what the eye measures, at 24px. See the nav pill below.

**Artwork on a rail gets optical overshoot; text sits on the rail exactly.**
A rail is measured by eye, not by bounding box, so a form that leads with a
curve has to cross the rail slightly to look level with the flat stems above
and below it. The desktop logo is the live case: at `pl-11` its ink and the
nav's "Mapa" label both landed within 1.5px of 44px, and the logo still read
as the more indented of the two, because its leading mark is a ~28px circle.
It carries `-ml-0.5` so the tangent sits at 42px and the mark's optical centre
reads at 44. Keep overshoots in the 1 to 3px band and spend them on curves and
on lockups that are much taller than the text opposite them, never on a text
label, which is already where it looks.

## 3. Color

**The app is light-only.** There is no dark theme and no `dark:` variant
anywhere in the codebase. Do not add one ad hoc; a partial dark mode is worse
than none. If a real dark theme is ever wanted it is its own project, with its
own pass over every token below.

### Surfaces
| Role | Value |
|---|---|
| App background | `bg-gray-50` |
| Header background | `bg-stone-50` |
| Footer background | `bg-stone-100` |
| **Glass panel** (the signature) | `border border-white/60 bg-white/80 shadow-sm backdrop-blur-md` |
| Glass panel, hovered | `hover:bg-white/90` |
| Glass panel, active/pressed state | `border-gray-900/30 bg-white/90` |
| Dialog surface (opaque) | `border border-gray-200 bg-white shadow-xl` |
| Dialog scrim | `::backdrop` `rgb(0 0 0 / 0.4)` + `blur(12px)` |
| Sheet scrim | `bg-black/20` |
| Opaque sheet | `bg-white` + `shadow-[0_-4px_20px_rgba(0,0,0,0.08)]` |
| Peek-state sheet | `bg-white/80 backdrop-blur-md border-t border-white/60` |
| Nested card | `bg-white` inside `bg-gray-100/80` |
| Row tint (expanded) | `bg-gray-50/60` |
| Inline detail block | `bg-gray-50` |

The glass recipe is the app's identity, and it belongs to *chrome that floats
in the workspace*: every floating map panel and chip uses it at `bg-white/80`.
It does **not** extend to dialogs. A dialog holds paragraphs of Spanish copy
over a saturated map, and at `bg-white/90` the map's colour still bled through
enough to push the `gray-500` body text under 4.5:1. Dialogs are opaque white
on a visible `gray-200` hairline; the scrim (dimmed and blurred, `/0.4`) is
what makes the panel read as floating, so the panel itself does not have to be
translucent to earn the effect. This is the Vercel / Linear / Stripe / GitHub
convention: translucency for HUD chrome, opaque paper for reading surfaces.

The glass recipe has a **reduced-transparency escape**, the same way every
looping animation has a reduced-motion one. A
`@media (prefers-reduced-transparency: reduce)` block in `app/globals.css`
drops `backdrop-blur-*` and takes every near-white translucent fill
(`bg-white/70` through `/95`) to solid `#fff`. It overrides the utilities in
place because the recipe is copied onto each component, not a shared class; if
a `.glass-*` class is ever introduced, the escape moves onto it. Scrims keep
their translucency, they carry depth rather than text. Nothing new is needed
per component: use the recipe and the escape already covers it.

### Text
| Role | Token | Notes |
|---|---|---|
| Primary heading / value | `text-gray-800` | dialog titles, active row labels |
| Panel title, body strong | `text-gray-700` | "Capas", "Calidad del Aire" |
| Secondary body | `text-gray-500` | paragraphs, summaries, muted labels |
| Nav resting label | `text-gray-600` | 4.5:1 floor, never `gray-400` |
| Tertiary / eyebrow | `text-gray-400` | uppercase micro-labels, icons |
| Counts, row summaries | `text-gray-500` | at `text-xs`; these carry data, so they clear 4.5:1 |
| Disabled / pending | `text-gray-500` | plus a `Próx.` badge |
| Inverse | `text-white` on `bg-gray-900` |

**Contrast rules that are already settled, do not undo them:**
- An unselected nav label is `gray-600`, not `gray-400` (2.5:1 fails).
- A dialog's close X is `gray-500`, not `gray-400` (needs 3:1 as the only exit).
- Counts and row summaries are `gray-500`. `gray-300` was 1.47:1 and is now
  reserved for pure furniture: the sheet grabber, an em-less placeholder dash.
- The Actualizado chip puts its *value* (the time) in `font-medium
  text-gray-700`; `gray-500` is only the quiet half ("Actualizado"), never a
  chip's only text.

### Air-quality scale
Never hardcode these. Import from `lib/air-quality.ts` (`IMECA_LEVELS`,
`getPM25Color`, `getQualityInfo`, `getLevel`).

Two tokens per level. `color` is the official NOM-172 hue, untouched, for
anything with **area**. `ink` is that same hue darkened (saturation held) until
it clears **4.5:1 on white**, for everything on a light ground that is **not** a
fill: the card's quality headline, hairlines and 1px rings, the sparkline dot
rings and threshold guides, the marker rim.

| Level | ≤ | `color` (fills) | `ink` (text ≥4.5:1, hairlines) |
|---|---|---|---|
| Buena | 15 | `#00e400` | `#0b7d2e` |
| Aceptable | 25 | `#ffff00` | `#8a6d00` (nudged to gold — no honest dark yellow) |
| Mala | 79 | `#ff7e00` | `#b45a00` |
| Muy mala | 130 | `#ff0000` | `#e00000` |
| Extremadamente mala | ∞ | `#8f3f97` | `#8f3f97` (already passes) |

`pm25 === null || pm25 <= 0.4` renders nothing at all, no gray marker.

On the **map**, a single marker's fill is that level's `color` nudged ~25%
toward its own `ink` (`getMarkerFill`, `MARKER_INK_MIX`), enough to take the
electric edge off IMECA yellow and green on the pale basemap without shifting
hue. Extrem. has `ink === color` and comes through untouched. The legend swatch
stays on the pure `color`, so a disc still reads back to its row. A resting disc
is then painted at 85% alpha (in `globals.css`, not in the mix) so that where
discs pile up in the basin the overlap reads as denser colour rather than one
disc masking another; the selected disc is solid. The marker **rim hairline**
(`--marker-edge`) and the selected-marker **pulse halo** split: the rim takes
`ink` (it must hold an edge over map imagery), the halo takes `color` (a large
soft fill wants full chroma).

On a chart, a **dot that stands for a single reading** takes the official
`color` for its body and that level's `ink` for its 1px ring, so a pale yellow
or green dot still holds an edge on the white plot. Both the sparkline's
always-on latest-hour dot and its hover dot follow this. The **quality headline**
in the estación card is `ink` (colored text, ≥4.5:1) — the status word is the
card's most important element and stays colored, not neutral. The **line and the
crosshair stay neutral** (`SPARKLINE_COLOR`): the path is one series, the
crosshair is a position cue, only the point is a value.

The sparkline's **IMECA threshold lines** (`IMECA_THRESHOLDS`, dashed, 55%) are
drawn in each opening level's `ink` — a 1px guide needs the darkened hue to be
visible at all.

## 4. Typography

Inter throughout. Sizes are deliberately small and the scale is short.

| Role | Classes |
|---|---|
| Hero metric (mobile sheet) | `text-3xl font-bold leading-tight` |
| Metric (desktop card) | `text-2xl font-bold` |
| Panel / dialog title | `text-base font-medium text-gray-700` (dialog: `text-gray-800`) |
| Card sub-title | `text-sm font-semibold text-gray-800` |
| Body | `text-sm leading-relaxed text-gray-500` |
| Row label | `text-sm font-medium` |
| Chip value | `text-[13px] font-medium text-gray-700` |
| Nav label | `text-sm font-medium`, current page `font-semibold` |
| Chip quiet label | `text-[13px] text-gray-500` |
| Eyebrow label | `text-xs font-medium uppercase leading-none tracking-wide text-gray-400` |
| Meta, counts | `text-xs text-gray-500` |
| Micro numbers, axis | `text-[11px] leading-none` / `text-[10px] font-medium` |
| Pending badge | `text-[10px] font-semibold uppercase tracking-wide` |
| Footer legal | `text-xs text-gray-400` |

Rules:
- `tracking-wide` is used **only** with `uppercase`. Nothing else gets tracking.
- `leading-none` on labels and single-line meta; `leading-relaxed` on any
  paragraph of Spanish copy.
- Weights in play: `font-medium` (500), `font-semibold` (600), `font-bold`
  (700). No `font-light`, no `font-extrabold`.
- Truncate rather than wrap in chrome: `min-w-0 flex-1 truncate`, and
  `whitespace-nowrap` on chips and buttons that must hold their width.
- The "label · summary" idiom is the house pattern for a collapsed header:
  bold label, then `· ` plus a muted summary.

### Copy
Spanish, sentence case, no em-dashes anywhere in user-facing text. Use commas
or periods. Section names are capitalized as products: "Capas", "Calidad del
Aire", "Sensores Ciudadanos", "Estaciones de Gobierno".

## 5. Components

### Radius scale
| Radius | Where |
|---|---|
| `rounded-full` | nav pills, dots, tooltips-as-chips, grabber |
| `rounded-3xl` (24px) | dialogs, bottom sheets (`rounded-t-3xl`) |
| `rounded-2xl` (16px) | floating panels, cards, grouped lists |
| `rounded-xl` (12px) | chips, FABs, buttons, nested cards, inline blocks |
| `rounded-lg` (8px) | icon buttons, focus targets on bare links/logos |
| `4px` (inline style) | the layer checkbox |

Bigger surface, bigger radius. Never mix two radii on nested containers by more
than one step.

### Icon sizes
Lucide icons, one of a small set of sizes. Match the row you are in rather than
picking a new value.

| Size | Where |
|---|---|
| `h-5 w-5` (20px) | nav-pill icons, the two mobile FAB glyphs (Navigation, Layers) |
| `h-4 w-4` (16px) | icon-button glyphs, the chevron in a list row's trailing rail |
| `h-3.5 w-3.5` (14px) | inline metadata icons in the sensor card (source glyph, copy / check) |
| `h-3 w-3` (12px) | info glyphs in the trailing rail |
| `h-2.5 w-2.5` (10px) | legend swatch dot |
| `h-2 w-2` (8px) | freshness dot |

The bottom-sheet grabber (`h-1 w-10`) is furniture, not an icon; its full spec
lives in Bottom sheet, below.

Trailing-rail *boxes* are their own thing and stay `h-7 w-7` (28px) whatever
glyph they hold, per List row, below; footer social buttons are `h-9 w-9` boxes.

Use `h-x w-x`, not the v3.4 `size-x` shorthand: the codebase is uniformly
`h-x w-x` and mixing the two makes them hard to grep.

### The map: markers only
No painted layer of any kind. Every attempt at one — clustering, density
heatmap, IDW gradient, IDW contour bands, an IQAir-style flat tint — was built
and pulled; the map is the basemap plus one DOM marker per reporting sensor.
Don't re-propose a painted surface without the user asking.

**Markers** (`.sensor-marker`, `createMarker` in `lib/air-quality.ts`). One
32px disc per visible sensor, flat at every zoom. Sizing *by zoom* was tried
and taken back out (a disc that shrank at metro zoom read as basemap furniture);
a flat 32 is a different lever, loosening the basin pile-up while the rim +
white ring + shadow hold the sensor read that a bare shrunk disc lost. Fill is
the level's `color` nudged ~25% toward its `ink` (`getMarkerFill`), painted at
85% alpha at rest (solid when selected), to calm IMECA yellow/green and let
overlaps read as density. Every marker is a real `<button>` with an `aria-label`
carrying
its full reading; focus ring is the solid `2px #111827` outline, not the house
ring, because the house ring vanishes over map imagery. No clustering. The
**active** marker — the selected sensor, else the default one the card opens on
(`DEFAULT_SENSOR_ID` = `"293003"`) — wears a pulsing halo in its own
air-quality ink and shows its PM2.5 number on a white core; every other marker
is a bare disc.

**Card.** At rest the desktop right column / mobile bottom sheet shows the
default sensor's card. Selecting a marker swaps it to that sensor. The card
carries the name, reading, 48h sparkline, coordinates and health recs.

### Interactive states

The button-like family shares one state model. **Rest** is the recipe in each
component block below; this table is only what the other states add. Nothing
here is conveyed by dimming alone (see §6).

| Component | Hover | Active / pressed | Focus |
|---|---|---|---|
| Nav pill | `hover:bg-black/[0.04]` (resting only) | current page carries a fill, not a press state | house ring |
| Mobile FAB | `hover:bg-white/90` | `border-gray-900/30 bg-white/90`, icon `text-gray-900` | house ring |
| Icon button | `hover:bg-gray-50 hover:text-gray-700`; in a tinted row `hover:bg-gray-200/70 hover:text-gray-600` | — | house ring |
| Secondary button | `hover:bg-gray-200` | — | house ring |
| List row | `hover:bg-gray-100/70` (on the `<div>` wrapper when the row has a trailing control) | expanded row sits on `bg-gray-50/60` | house ring **+ `ring-inset`** |
| Glass panel header | `hover:bg-white/90` | `border-gray-900/30 bg-white/90` | house ring |

**House ring** = `focus-visible:outline-none focus-visible:ring-2
focus-visible:ring-gray-900/15`, plus `focus-visible:ring-inset` on full-bleed
rows. Map markers are the sole exception (`2px #111827` solid outline, §5 map).
A **dead / not-yet-live** control is never a greyed, `disabled` button: it keeps
its resting look and gains a `Próx.` badge and its `z-20` tooltip. A real
disabled state (`text-gray-500` + a `Próx.` badge, per §3 Text) appears only
where an action genuinely exists but is unavailable right now.

### Nav pill (shared, both breakpoints)
```
flex items-center gap-2 rounded-full border border-transparent px-5 py-2.5
transition-colors focus-visible:outline-none focus-visible:ring-2
focus-visible:ring-gray-900/15
```
- Current: mobile `border-blue-200 bg-blue-50 text-blue-600`; desktop
  `md:border-white/60 md:bg-white md:text-gray-700 md:shadow-sm`.
- Resting: `text-gray-600 hover:bg-black/[0.04]`.
- **The desktop fill is dropped while only one link is live.** A filled pill is
  a *surface*, so its edge lands on the 24px surface rail while the bare logo
  opposite it sits on the 44px text rail, and the bar's two insets stop
  matching. With one link the fill is also marking a choice that does not
  exist. Unfilled, the label returns to the text rail; `md:text-gray-700`,
  `font-semibold` and `aria-current` still carry the state. `navlinks.tsx`
  derives this (`soloOnDesktop`), so the fill returns when a second link ships.
- The pill class goes on the `<Link>` itself, never on a div inside it, so the
  hit area and the focus ring match what you see.
- Icons are `h-5 w-5` with `aria-hidden="true"`; `aria-current="page"` carries
  the state for assistive tech.

### Icon button

```
hover:text-gray-700
```
Inside a tinted row: `text-gray-400 hover:bg-gray-200/70 hover:text-gray-600`.
Icons `h-4 w-4`, info glyphs `h-3 w-3`.

### List row (Capas)
```
flex w-full items-center gap-3 border-t border-gray-100 px-4 py-3.5 text-left
transition-colors hover:bg-gray-100/70
focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-inset
focus-visible:ring-gray-900/15
```
Grouped container: `overflow-hidden rounded-2xl border border-gray-200
bg-white`. Nested rows indent `ml-11` and drop to `py-3`. A trailing count is
`flex-shrink-0 text-xs text-gray-500`.

**The 44px trailing rail.** Every row in a grouped list ends its content at
`pr-2` and then terminates in a **28px control box** carrying `mr-2`, so all
counts, summaries and glyphs land on one rail 44px from the card edge:

| Trailing element | Box |
|---|---|
| Info button | `mr-2 rounded-lg p-2` + `<Info className="h-3 w-3" />` |
| Chevron button | `mr-2 rounded-lg p-1.5` + `<ChevronRight className="h-4 w-4" />` |
| Nothing | `<span aria-hidden="true" className="mr-2 h-7 w-7 flex-shrink-0" />` |

A row that carries no control still reserves the slot. Never hand-compute the
inset as a `pr-[...]` value; it drifts the moment the button's padding changes.
Rows with a control are a `<div>` wrapper holding the hover and the `border-t`,
with the content `<button>` as `min-w-0 flex-1` inside it.

### Bottom sheet
`fixed left-0 right-0 rounded-t-3xl bg-white shadow-[0_-4px_20px_rgba(0,0,0,0.08)] md:hidden`,
grabber `mx-auto mb-3 h-1 w-10 rounded-full bg-gray-300/60` in a
`cursor-grab select-none` header, body
`flex-1 overflow-y-auto overscroll-contain px-5 pb-8`, capped at `max-h-[70svh]`.

### Dialog
Native `<dialog>` via `DialogShell` / `InfoDialog`. Shell:
`flex max-h-[85svh] w-[85%] max-w-md flex-col overflow-hidden rounded-3xl
border border-gray-200 bg-white p-8 shadow-xl`. Opaque, not glass, for the
reason in §3 Surfaces: the body copy is `gray-500` and it cannot hold 4.5:1
over a map that shows through. The scrim carries the depth
(`::backdrop`, `rgb(0 0 0 / 0.4)` + `blur(12px)`), so the panel does not need
to. Header never scrolls (`flex-shrink-0`), body does
(`min-h-0 flex-1 overflow-y-auto overscroll-contain`). Escape routes through
`onCancel` into React state; outside-click requires both mousedown and click to
land outside.

### Tooltip

Two kinds, split by **where they sit**, not by how much they hold:

- **Hint tooltip** (an icon's label, a `Próximamente` on a dead control): dark,
  transient, single line. `pointer-events-none ... rounded-lg bg-gray-900 px-3
  py-1.5 text-xs text-white shadow-sm`. It floats over arbitrary page content
  and has to read as system feedback, not a surface, so it is dark with no
  border. This is the one place the `bg-gray-900` tooltip token holds. Live
  case: the mobile nav tooltip in `navlinks.tsx`.
- **Chart tooltip** (anything anchored inside a chart's plot area, whether it is
  a multi-row hover card or a single-line timestamp label): light, near-solid.
  `bg-white/95`, `border border-black/[0.08]`, `backdrop-blur-[6px]`,
  `shadow-[0_6px_24px_rgba(0,0,0,0.1)]`, dark text (`text-gray-700`, values in
  `font-medium`). Radius follows size: `rounded-xl` for a padded multi-row card
  (`dias-insalubres`, padding `16px 22px`), `rounded-lg` for a single-line pill
  (the `Sparkline` hover in `mapa-sensors.tsx`). Not the glass recipe: readouts
  have to stay crisp, so contrast beats transparency the same way it does in a
  dialog. The hairline is `black/[0.08]`, not `white/60`, because `white/60` is
  invisible on a near-opaque white ground; the shadow does the lifting that a
  dark fill used to.

A chart tooltip stays light even when it carries only a label: one rule per
surface beats a per-tooltip judgement call that the code keeps re-litigating.

**Placement.** A chart tooltip tracks the cursor on the x axis only and is
pinned to a fixed y just inside the plot area's top edge (`top: 0`,
`translate(-50%, 6px)`), so it holds still while the cursor scrubs instead of
riding the line. It never crosses the plot area's top edge: on the sensor card
the PM2.5 headline sits directly above, and a tooltip over that edge covers the
reading the hover is meant to explain. Pad the value domain (here 15%) so the
line's peak never reaches the pinned band. Clamp the x offset so the box stays
inside the card (`clamp(70px, <x>%, calc(100% - 70px))`). This is the
Vercel / Stripe / GitHub-analytics convention; a tooltip that follows the
pointer in both axes and flips to the left near the right edge is the
*pointer-anchored* pattern, for hovers that snap to the mouse rather than to a
data point, and is not used here.

### Focus
One ring everywhere:
```
focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-gray-900/15
```
Add `focus-visible:ring-inset` on full-bleed rows so the ring is not clipped.

### Motion
| Effect | Value |
|---|---|
| Color / background | `transition-colors` unqualified (150ms) for incidental tint; `duration-200` on anything the user directly drives (pills, FABs, icon buttons, chevrons); `duration-300` on scrims and full-panel fades only |
| Chevron disclosure | `transition-transform duration-200` + `rotate-90` when open (`-rotate-90` for a panel that opens upward) |
| Scrim | `transition-opacity duration-300` |
| Disclosure body | `.disclosure-in`, 180ms ease-out, fade + `translateY(-4px)`; `.disclosure-in-up` is the mirror (`translateY(4px)`) for a panel that opens upward |
| Dialog | `dialog-in` 160ms ease-out, fade + `scale(0.97)`; backdrop fades with it |
| Marker hover | `transform: scale(1.12)` on the dot, 0.15s ease |
| Marker selected | `marker-pulse` 2.4s ease-out infinite, halo behind the dot |
| Fresh-data dot | `animate-ping` on the green halo only |
| Map camera | one opening `flyTo`, `OPENING_MOVE_MS` (4500ms), no custom easing, from zoom 8 to the default sensor at zoom 13 (fallback `10.5`); `jumpTo` under reduced motion |

Chevrons rotate, they are never swapped for a different glyph, and they rotate
**toward the content they reveal**: down for a panel that opens downward, up for
one that opens upward. A disclosure anchored to the foot of its column (the
desktop air-quality legend) keeps its trigger row on the bottom edge and
unfolds the body into the gap above it, so the row you just clicked holds
still; use `flex-col-reverse` to paint the trigger last while keeping it first
in the DOM, so tab and screen-reader order stay trigger-then-body. Disclosures
animate **in only**; an exit animation would keep controls in the tab order
after they are visually gone.

**Map camera.** One move: the opening `flyTo`. The map is constructed at zoom 8
over the metro (`OPENING_CENTER`) and a single `flyTo` settles it in on the
default sensor at zoom 13 — the "standing beside it" framing — or the metro at
`10.5` if nothing is reporting. Runs once (`didOpeningFlyRef`). There is no
locate-me: this is an open-data map of the airshed, not a personal "air near me"
readout.

Use `flyTo`, not `easeTo`, for any move over ~2 zoom levels: `flyTo` runs the
van Wijk-Nüij curve that holds *perceived* zoom speed constant, where `easeTo`
interpolates the zoom number linearly and the view accelerates into the stop,
which reads as slow-then-lunge. Do not hand `flyTo` a custom `easing`; its curve
is already tuned. The 4.5s duration replaced 3s, which over five zoom levels
read as a lunge. Padding is set instantly (not interpolated alongside the fly,
which looked like the map veering sideways). `essential: true` keeps the move
from being dropped when the tab is backgrounded, so it is paired with a
`prefersReducedMotion()` check that swaps the whole move for a `jumpTo` to the
same framing. `easeTo` is only for small nudges, a level or two, a position or
bearing tweak.

Every looping animation has a reduced-motion escape: either
`motion-reduce:animate-none` in Tailwind, or a
`@media (prefers-reduced-motion: reduce)` block in `globals.css` that stops the
animation and leaves a static low opacity. The non-looping exception, the
opening camera, gets its escape in JS (`jumpTo`) for the reason above.

## 6. Accessibility invariants

These were fixed deliberately. Preserve them in anything new.

- Text hits 4.5:1, non-text controls hit 3:1. That is why the gray tokens above
  are the values they are.
- Color is never the only channel. The freshness dot is backed by a real
  timestamp; the map marker prints its own PM2.5 number.
- Every icon-only control has `aria-label`; decorative icons get
  `aria-hidden="true"`.
- Disclosures wire `aria-expanded` + `aria-controls`, and the panel stays
  mounted with `hidden` so `aria-controls` always resolves.
- Async status is announced through a separate `role="status"` node
  (`sr-only`), not by mutating a disabled button's label.
- Messages persist until dismissed. Nothing important disappears on a timer.
- External links carry `<span className="sr-only"> (abre en una nueva pestaña)</span>`.
- Transparency has an escape: `prefers-reduced-transparency: reduce` is handled
  globally in `globals.css` (see §3 Surfaces). Every glass surface goes opaque;
  the map-marker white core and drop shadow already keep markers separable
  without it.
- **Forced colors (Windows High Contrast) is not yet handled, and is the next
  real gap.** The glass edges (`border-white/60`), the marker white ring, and
  the layer checkbox's inline hex all vanish when the OS replaces the palette.
  When it is addressed: do it in one `@media (forced-colors: active)` pass over
  every token, lean on system colors (`Canvas`, `CanvasText`, `ButtonBorder`,
  `Highlight`), and keep `forced-color-adjust: none` only where an air-quality
  fill genuinely must survive (the legend swatches, the markers). A half pass is
  worse than none, same rule as the dark theme in §3.

## 7. Quick checklist for a new component

1. Floating over the map? Glass recipe, `rounded-2xl`, on the 24px surface rail.
   Reduced-transparency is handled globally, add nothing per component.
2. Header text? `px-5 pt-4 pb-3`, `text-base font-medium text-gray-700`.
3. Body copy? `text-sm leading-relaxed text-gray-500`.
4. Eyebrow? `text-xs font-medium uppercase leading-none tracking-wide text-gray-400`.
5. Rows? `py-3.5`, `border-t border-gray-100`, `hover:bg-gray-100/70`.
6. Any focusable element? The `ring-2 ring-gray-900/15` ring, no exceptions.
7. Any animation? A reduced-motion fallback.
8. Any air-quality color? From `lib/air-quality.ts` (see Constants index).
9. Any Spanish copy? Sentence case, no em-dashes.
10. Reusing a named value (padding const, sensor id, camera setting)? Import it,
    do not re-type the literal. If it is a third copy of an inline value, lift it
    to a const.
11. Verify with `pnpm exec tsc --noEmit` then `pnpm build`. `pnpm lint` is
    currently broken in this repo, so it is not the gate. `pnpm build` always
    logs one `DYNAMIC_SERVER_USAGE` warning on the home route; that one is
    expected.
